# Magic Actions for YouTube — Журнал изменений

## Сессия 1: Первый запуск и поиск ошибок

### Что было
Кастомная урезанная копия расширения Magic Actions for YouTube (MV3). Единственная функция — переключение светлой/тёмной темы на YouTube.

### Найденные ошибки (по порядку)

| # | Ошибка | Где | Следствие |
|---|--------|-----|-----------|
| 1 | `f6=8` вместо `f6=80000` для светлой темы | content.js `syncCookie()` | YouTube не распознавал значение, после reload тема откатывалась |
| 2 | Точное сравнение `f6 === '400'` | content.js `getThemeFromCookie()` | Ломалось на склеенных флагах (`40080000`) |
| 3 | `location.reload()` после каждого toggle | content.js | Перезапуск видео, циклы перезагрузок у залогиненных |
| 4 | Не блокировался `toggleAttribute('dark')` | main_world.js | YouTube обходил патч → смешанная тема |
| 5 | Классы `__ytnight`/`__ytday` стирались при SPA | content.js | CSS-переменные отваливались |
| 6 | `normalize()` терял 'light' | content.js | Выбор пользователя перезаписывался кукой |
| 7 | YouTube перезаписывает PREF (f6) | main_world.js | После reload тема откатывалась |

## Сессия 2: Первый набор исправлений

### Изменения в content.js
- **syncCookie**: `f6=80000` вместо `f6=8` (как в оригинальном расширении)
- **getThemeFromCookie**: чтение по префиксу `f6.charAt(0) === '4'` вместо точного сравнения; фолбэк на атрибут `dark` если куки нет
- **Убран `location.reload()`** — тема применяется живьём
- **Убраны классы `__ytnight`/`__ytday`** — работаем только с нативными атрибутами `dark`/`light`
- **Добавлен `syncSearchboxClasses(theme)`** — ручная синхронизация классов `*Dark` у строки поиска (симметрично: dark→доставить, light→снять)
- **Добавлен `attrGuard`** — MutationObserver на атрибуты `dark`/`light` у `<html>`: в dark-режиме держим атрибуты, в light-режиме следим за родным тумблером
- **Добавлен `bodyGuard`** — пересоздание тумблера при его удалении из DOM

### Изменения в main_world.js
- **Заблокирован `toggleAttribute('dark')`** в дополнение к `setAttribute`/`removeAttribute`
- **Перехват cookie-setter** — в dark-режиме в любом записываемом `PREF=…` ставим `f6=400`
- **Добавлен `data-ma-notify` dispatcher** — MutationObserver на метку → dispatch `CustomEvent('yt-action')`

### Изменения в styles.css
- Убрана светлая тема (ни одного правила для light)
- Оставлена только тёмная тема `html[dark]` + кнопка тумблера

### Результат
Переключение заработало, но **только scrollbar меняет цвет**. Остальная страница — без изменений.

## Сессия 3: CDP-диагностика

### Запуск тестового Chrome
- Профиль: `/tmp/ma_test_profile`
- Порт CDP: 9222
- Расширение загружено через `--load-extension`

### Найдено через CDP
1. YouTube хранит цвета в **обфусцированных токенах `--t*`** (не `--yt-spec-*`), определённых на `html[dark]`/`html[light]`
2. В `:root` — **тёмный дефолт** → снять `dark` без постановки `light` = страница чёрная
3. Компонент `yt-searchbox` ставит классы `*Dark` при рендере по `hasAttribute('dark')` и **не следит за атрибутами**
4. YouTube уведомляет компоненты экшеном `yt-dark-mode-toggled-action` через `CustomEvent('yt-action')`

### Решение: философия v3
**Светлая тема = "расширение выключено"**: ставим только `light=""` + кук `f6=80000` + чистим классы `*Dark`. YouTube сам красит. В styles.css — ноль правил для light.

## Сессия 4: Применение рекомендаций LMArena (gemini-3-flash)

### Консультация: ключевые вопросы
1. Достаточно ли `setAttribute('light', '')` для активации токенов `--t*`? → **Да, CSS-каскад работает**
2. Нужен ли дебаунс перед dispatch CustomEvent? → **Да, 100мс**
3. Формат `args` в событии? → **boolean: `[true]`/`[false]`**
4. Нужно ли патчить `window.yt.config_`? → **Нет, перезаписывается YouTube**
5. Нужен ли forced re-layout? → **Нет, CSS-токены обновляются синхронно**

### Изменения в main_world.js (финальные)

**Было:**
```js
detail: {
  actionName: 'yt-dark-mode-toggled-action',
  optionalAction: false,
  args: [isDark],
  returnValue: []
}
```

**Стало:**
```js
if (notifyTimer) clearTimeout(notifyTimer);
notifyTimer = setTimeout(function () {
  var isDark = v === 'dark';
  (document.body || document.documentElement).dispatchEvent(
    new CustomEvent('yt-action', {
      bubbles: true,
      composed: true,
      detail: {
        actionName: 'yt-dark-mode-toggled-action',
        args: [isDark]
      }
    })
  );
}, 100);
```

**Что изменено:**
1. **Убраны** `optionalAction` и `returnValue` — избыточны
2. **Добавлен debounce 100мс** — YouTube успевает завершить внутренние обновления
3. **`isDark` — boolean** `true`/`false` (был `v.indexOf('dark') === 0`, тоже boolean, но проверено)
4. **`v === 'dark'`** вместо `v.indexOf('dark') === 0` — точное сравнение

## Текущее состояние

### Работает
- Тёмная тема: полная (фон, текст, компоненты, строка поиска)
- Светлая тема: полная (нативный вид YouTube)
- Переключение живьём, без reload
- Тумблер на странице + popup
- Синхрузация во всех вкладках через chrome.storage
- Родной тумблер YouTube подхватывается (attrGuard)
- Кука PREF сохраняется при перезагрузке
- SPA-навигация (yt-navigate-finish)

### Известная проблема
**Задержка поиска при dark→light**: при переключении на светлую тему элементы строки поиска (поле, кнопка, иконки) становятся светлыми не сразу, а через какое-то время. Причина: `syncSearchboxClasses('light')` снимает классы `*Dark`, но компонент `yt-searchbox` может перерисовываться с задержкой (PropertyValueEffects, рендер-цикл YouTube). Нужно выяснить, как заставить компонент перерисоваться мгновенно.

## Сессия 5: Устранение задержки поиска при dark→light

### Проблема
При переключении на светлую тему строка поиска (поле, кнопка, иконки) становилась светлой через 0.5–2 секунды вместо мгновенно.

### Консультация с gemini-3-flash (4 раунда)
1. **Рендер-pipeline yt-searchbox**: Polymer 3 (PropertyEffects). Читает `hasAttribute('dark')` ОДИН раз при `connectedCallback()`, кэширует как свойство `this.darkTheme`. За атрибутами НЕ следит — слушает `yt-dark-mode-toggled-action`.
2. **Ручное снятие классов — вредно**: компонент перерисовывается по своему циклу и снова ставит `*Dark` из кэшированного свойства. Гонка между ручной чисткой и внутренним рендером = видимая задержка 0.5–2с.
3. **Цепочка обновления**: event → property update → Polymer observer → requestUpdate() (microtask) → render() (synchronously) → paint (следующий animation frame ≈ 16–33мс).
4. **Debounce 100мс — вреден**: нативный тумблер YouTube dispatch'ит сразу. Debounce создавал окно, в котором внутренние рендер-циклы YouTube переставляли тёмные классы обратно.
5. **ytd-masthead** слушает то же событие — ручное управление классом `dark` НЕ нужно.
6. **Формат события**: минимальный `{actionName: 'yt-dark-mode-toggled-action', args: [boolean]}`. `optionalAction` и `returnValue` не нужны.
7. **Target dispatch**: `document.documentElement` надёжнее `document.body` (хотя оба работают, событие всплывает).

### Изменения

**content.js:**
- Удалена функция `syncSearchboxClasses(theme)` — вся ручная работа с классами `*Dark`
- Удалена функция `syncSoon(theme)` — ретраи 300мс/1200мс
- Удалены константы `DARK_CLASSES` и `BASE_CLASSES`
- Из `applyTheme()` убраны вызовы `syncSoon('dark')`/`syncSoon('light')`
- Логика `applyTheme()` упростилась: атрибуты + кука + sessionStorage + notify

**main_world.js:**
- Убран debounce 100мс — dispatch происходит сразу из MutationObserver
- Target dispatch: `document.documentElement` (был `document.body || document.documentElement`)
- Комментарий обновлён (убрано упоминание ручных классов)

### Почему это правильно
Теперь весь цикл переключения темы выглядит так:
```
content.js (ISOLATED)          main_world.js (MAIN)          YouTube
┌─────────────────┐            ┌──────────────────┐          ┌─────────────┐
│ setAttribute    │            │ MutationObserver │          │  yt-searchbox│
│ dark/light      │            │ видит data-ma-   │          │  слушает    │
│ syncCookie      │            │ notify           │          │  event      │
│ data-ma-notify  │──метка───► │                  │──event──►│  обновляет  │
│ sessionStorage  │            │ dispatch сразу   │          │  darkTheme  │
└─────────────────┘            └──────────────────┘          └─────────────┘
```

Никакой ручной чистки классов → никакой гонки. Компонент сам управляет своим состоянием через событие (как родной тумблер YouTube).

### Ожидаемый результат
Поиск переключается за 16–33мс (один animation frame) вместо прежних 0.5–2 секунд.

## Сессия 6: Возврат бага «светлый поиск в тёмной теме» — регресс от удаления ручного синка

### Симптом
После сессии 5 (удаление `syncSearchboxClasses`) **light→dark сломался**: у `yt-searchbox` поле/кнопка поиска остаются светлыми навсегда. DOM-дамп показал **смешанное состояние**: `Host`/`InputBox`/`SearchButton` без `*Dark` (светлые), а `SuggestionsContainerDark` присутствует.

Асимметрия доказывает: консультация модели («компонент сам перерисуется от события») была **неверной для этого билда YouTube** — dark-покраска поиска держится на *КЛАССАХ* (хардкоды), а не на токенах `--t*`. Без классов dark-варианта — останется светлым. В старом разборе бандла прямо сказано: поиск рендерится ТОЛЬКО при смене page-type (`.hasAttribute("dark")` читается при connectedCallback/рендере), а НЕ от экшенов.

### Консультация с gemini-3-flash (4 раунда)
1. **Событие не панацея** — анализ бандла (render-once) правдоподобнее, чем Lit-перерисовка от CustomEvent.
2. **`requestUpdate()`** — правильный способ заставить компонент перечитать живой `hasAttribute('dark')`: DI-токен `SLo = () => document.documentElement.hasAttribute('dark')` — ленивая функция, вызывает `hasAttribute` при каждом рендере. → смена атрибута + `requestUpdate()` = классы пересчитаются правильно.
3. **Ручная смена классов безопасна**: YouTube перерисовывает поиск при навигации и сам читает атрибут → самокоррекция. Ручные классы «временные», живут до следующего рендера. Вероятность конфликта < 1%.
4. **75 мс** — один короткий ретрай догоняет повторные рендеры YouTube; долгие 300/1200 — создавали гонку.
5. **Полный инвентарь `*Dark`**: 9 пар base→dark (Host, InputBox, Input, SearchButton, SuggestionsContainer, ClearButton, VoiceButton, Desktop, SuggestionsItem).

### Ошибка в коде модели (исправлена при реализации)
Модель в Q7 предлагала вешать ВСЕ `*Dark` классы на сам `yt-searchbox` (`.classList.toggle(darkClass, isDark)` на хосте). По реальному DOM это неверно: `InputBoxDark` — на вложенном `<div>`, `SearchButtonDark` — на кнопке, `HostDark` — на хосте. Исправил на **descendant-targeting**: найти элемент по базовому классу → повесить dark-вариант на НЕГО. Нет базового класса → no-op.

### Изменения в content.js
- **Возвращён `syncSearchboxClasses(theme)`** (descendant-targeting по `DARK_CLASS_MAP`, 9 пар)
- **Добавлен `requestUpdate()`** на `yt-searchbox` и `ytd-masthead` (после смены классов) — Lit-компоненты перечитывают живой атрибут и рендерятся заново, самокоррекция
- **`ytd-masthead`**: `classList.toggle('dark', isDark)` + `requestUpdate()`
- **Один ретрай 75 мс** в `applyTheme()` (через `_maSearchRetry`, `clearTimeout` перед новым)
- Функция вызывается СИНХРОННО сразу после установки атрибутов (T=0) — мгновенный визуал
- **main_world.js не тронут**: dispatch события без debounce, как в сессии 5

### Почему dark→light не вернёт задержку
- Нет debounce (сессия 5 его убрала) — событие уходит сразу
- Нет долгих ретраев 300/1200мс — только один 75мс
- `requestUpdate()` заставляет компонент перечитать живой `hasAttribute('dark')` — если YouTube вернёт `dark` обратно, классы не разъедутся
- Ручные классы + `requestUpdate` не дерутся: классы дают мгновенный визуал, Lit-рендер либо подтверждает (no-op), либо корректирует

### Ожидаемый результат
- light→dark: поиск темнеет мгновенно (классы добавлены в T=0 + requestUpdate)
- dark→light: поиск светлеет мгновенно (без задержки, как в сессии 5)

## Сессия 7: Атрибут `dark` на `ytd-masthead` — недостающее звено из оригинала

### Диагноз
Баг «поиск застрял в старой теме» НЕ лечился классами/событиями, потому что в CSS
сегодняшнего YouTube тёмные токены поиска заданы селектором **`[dark],html[dark]`** —
атрибут `dark` на ЛЮБОМ элементе (не только на `<html>`!) включает тёмные значения
custom-properties в его поддереве:

- `--ytd-searchbox-background`: дефолт `hsl(0,0%,100%)`, тёмный `hsl(0,0%,7%)` под `[dark]`
- `--ytd-searchbox-legacy-button-color`: дефолт `#f8f8f8`, тёмный `hsla(0,0%,100%,.08)` под `[dark]`
- цвет текста хоста `--tffc2fd3a644f6275`: `#0f0f0f` в `:root`, `#f1f1f1` под `[dark]`
- фон шапки `--t3e41d7b17b187f69`: `#fff` в `:root`, `#0f0f0f` под `[dark]`
- СВЕТЛЫЙ дефолт живёт в `:root` (`initial`-токены — это ОТДЕЛЬНАЯ вырожденная
  перечисляющая группа), `html[light]` в этом билде НЕТ — ставим `light=""` для
  страховки, но красить обратно помогает снятие `dark`.

### Корень (из оригинала!)
Оригинальное расширение — **ImprovedTube** (v4.2081, преемник Magic Actions for
YouTube от Александра Белова; CRX `lodjfjlkodalimdjgncejhkadjhacgki`, источник
`/tmp/ma_crx/ext_lodjfjlkodalimdjgncejhkadjhacgki`) — в `themes.js` при переключении
ставит/снимает атрибут `dark` **и на `<html>`, и на `ytd-masthead`**:

```js
case 'dark':
    document.documentElement.setAttribute('dark', '');
    document.querySelector('ytd-masthead')?.setAttribute('dark', '');
    // + f6=400
case 'light':
    document.documentElement.removeAttribute('dark');
    document.querySelector('ytd-masthead')?.removeAttribute('dark');
    // + f6 снять
```

Мы ставили на masthead только КЛАСС `dark` (класс не срабатывает: селектор
`ytd-masthead.dark` есть, но токены-красители живут под `[dark]` АТРИБУТОМ). Поэтому:
- light→dark: поиск оставался светлым — masthead-поддерево не получало тёмных токенов
- dark→light: поиск оставался тёмным — снятие класса НЕ снимало `[dark]`-токены,
  если на masthead оставался неубранный атрибут

Оригинал НЕ трогает классы `*Dark`, НЕ диспатчит `yt-action`, НЕ ставит `light=""` —
это всё наша надстройка; она работала нестабильно, потому что боролась с CSS токенами
вместо того, чтобы включить их нативным механизмом.

### Изменение (content.js `syncSearchboxClasses`)
- **dark**: `ytd-masthead.setAttribute('dark','')` + `classList.toggle('dark', true)` (класс — страховка второго слоя) + `requestUpdate()`
- **light**: `ytd-masthead.removeAttribute('dark')` + `classList.toggle('dark', false)` + `requestUpdate()`
- Синтаксис проверен: `node --check` OK у content.js и main_world.js
- main_world.js БЕЗ изменений: он блокирует setAttribute/removeAttribute только на
  `document.documentElement`, masthead не перехватывает — конфликта нет.

### Почему это теперь симметрично
- Токены `[dark]` реагируют на атрибут СРАЗУ (custom properties, без перерисовки) —
  мгновенный визуал без Lit-рендера
- Классы `*Dark` + `requestUpdate` продолжают доставлять JS-сторонние стили (цвет иконок
  `#fff`, хардкоды) как второй слой
- Снятие атрибута в light убирает и токены, и перестаёт действовать селектор
  `ytd-masthead[is-watch-page][dark]` (прозрачная шапка на watch-страницах)

### Проверки
- `node --check` обоих скриптов — OK
- Доказательная база: `/tmp/kevlar_base.css` (скачан сегодня), `/tmp/yt_home.html`,
  исходник оригинала `/tmp/ma_crx/ext_lodjfjlkodalimdjgncejhkadjhacgki/js&css/web-accessible/www.youtube.com/themes.js`

### ✅ ПОДТВЕРЖДЕНО: решение заработало
Пользователь подтвердил: **кнопка работает, тема переключается как надо, обе стороны
мгновенно**. Это финальная рабочая конфигурация (Сессии 2–7 суммарно):

```
applyTheme(theme):
  1. html: setAttribute('light'/'dark') + removeAttribute(противоположный)
  2. syncSearchboxClasses(theme)  →  T=0, синхронно:
       a. классы *Dark на РАЗНЫХ потомках (9 пар из DARK_CLASS_MAP)
       b. ytd-masthead: АТРИБУТ dark (set/remove) + КЛАСС dark + requestUpdate()
       c. yt-searchbox: requestUpdate()
  3. один ретрай 75 мс (не 300/1200!)
  4. sessionStorage + syncCookie(f6) + updateToggleIcon
  5. data-ma-notify → main_world.js диспатчит yt-action сразу, БЕЗ debounce
```

### 0. Финальная работающая архитектура (что именно работает)

| Файл | Что делает | Ключевые строки |
|------|-----------|-----------------|
| `content.js` (ISOLATED) | Атрибуты `<html>`, классы/атрибут masthead, тумблер, guards, storage | `applyTheme()`, `syncSearchboxClasses()`, `DARK_CLASS_MAP`, `attrGuard`, `bodyGuard` |
| `main_world.js` (MAIN) | Патчи set/remove/toggleAttribute + cookie (dark-only) + dispatch yt-action | строки 18–45 (блоки), 53–79 (cookie), 88–116 (notify-observer) |
| `styles.css` | ТОЛЬКО тёмная тема `html[dark]` + кнопка тумблера. Светлая = СТРАХОВКА: ноль правил! | — |
| `popup.*` | Toolbar-кнопка (chrome.storage.local) | — |

**Философия (критична!):** `dark` = «расширение включено» (форсим атрибуты+куку,
блокируем перезапись). `light` = «расширение выключено» (только нативные светлые
атрибуты + кука, дальше YouTube сам; никаких наших правил для светлой).

### 1. Как YouTube хранит тему (факты, проверенные на реальном билде)

- Кук `PREF` параметр `f6` — битовая маска. Бит 165 = 0x400 (dark), бит 174 = 0x80000
  (light). YouTube **склеивает** флаги (`40080000`) → ЧИТАТЬ по ПЕРВОМУ символу:
  `f6.charAt(0) === '4'` = dark. Никаких точных сравнений на `=== '400'`!
- Цвета страницы — обфусцированные токены `--t*` (напр. `--t3e41d7b17b187f69`),
  определённые на селекторе `[dark],html[dark]` / в `:root`. В 2025+ билде
  `html[light]`-селектора НЕТ, `:root` содержит `initial`-заглушки + светлые
  дефолты; тёмные значения — под `[dark]`-атрибутом.
- **`[dark]` без `html` = атрибут `dark` на ЛЮБОМ элементе включает тёмные токены
  в его поддереве.** Это ГЛАВНОЕ открытие: `ytd-masthead[dark]` сам по себе
  перекрашивает поиск, даже если `<html>` светлый.
- Атрибуты `dark`/`light` на `<html>` судя по CSS — да, `[light],html` тоже есть;
  наша пара dark+light на html = проверенная безопасная комбинация.
- Компонент `yt-searchbox` красится СМЕШАННО: частично токенами, частично
  хардкодами через классы `ytSearchboxComponent*Dark` (например `.HostDark{color:#fff}`).

### 2. Анти-паттерны — путь, по которому НЕ надо ходить (все опробованы!)

| # | Неверный шаг | Почему провалился | В какой сессии |
|---|--------------|-------------------|----------------|
| 1 | `f6=8` для light (вместо `80000`) | YouTube не распознавал, тема откатывалась после reload | 1 |
| 2 | Точное сравнение `f6 === '400'` | Ломалось на склейке `40080000` | 1 |
| 3 | `location.reload()` после toggle | Перезапуск видео, циклы у залогиненных | 1 |
| 4 | Собственные классы `__ytnight`/`__ytday` + CSS-переопределения | «Правила для светлой ломали нативный вид»: полоска белая / слишком белая страница | 1–2 |
| 5 | Не блокировать `toggleAttribute` | YouTube обходил патч set/removeAttribute | 1 |
| 6 | НЕ ставить `light=""` при светлой (боялись лишнего) | Страница оставалась чёрной (старый билд, тёмный дефолт в :root) — ставим ВСЕГДА | 3 |
| 7 | **Debounce 100 мс перед dispatch yt-action** | Создавал окно, пока YouTube вернёт тёмные классы обратно | 4→удалён в 5 |
| 8 | **Полное удаление `syncSearchboxClasses`** (доверие консультации «сам перерисуется») | light→dark сломался: поиск светлый навсегда (DOM-дамп: Host/InputBox/SearchButton без *Dark, а SuggestionsContainerDark есть — смешанное состояние!) | 5 |
| 9 | **Долгие ретраи 300/1200 мс** | Дрались с внутренним рендером YouTube | 2 и 6 |
| 10 | **Вешать ВСЕ классы *Dark на хост `yt-searchbox`** (совет модели Q7) | Классы в реальном DOM НА РАЗНЫХ элементах → уезжали не туда | 6 |
| 11 | **Ставить на masthead только КЛАСС `dark`, без АТРИБУТА** | Класс не включает `[dark]`-токены! Нужен `setAttribute('dark','')` | 6→7 |
| 12 | **`syncSearchboxClasses` с ретраями вместо немедленно** | Задержка dark→light 0.5–2 с | 4 |

### 3. Правильный путь (итог)

1. **dark**: на `<html>` `setAttribute('dark')` + снять `light`; на `ytd-masthead`
   `setAttribute('dark')` + класс `dark` + `requestUpdate()`; доставить все 9 пар
   `*Dark`-классов на их ОТДЕЛЬНЫЕ элементы; кука `f6=400`; `data-ma-notify`→yt-action.
2. **light**: на `<html>` `setAttribute('light')` + снять `dark`; на `ytd-masthead`
   снять атрибут `dark` и класс `dark`; снять `*Dark`-классы; кука `f6=80000`.
3. Один короткий ретрай **75 мс** — догоняет поздний ререндер, НО не дерётся.
4. Dispatch yt-action **без debounce**, сразу, с `document.documentElement` как target.
5. `requestUpdate()` на Lit-компонентах — они перечитывают живой
   `hasAttribute('dark')` (DI-токен `SLo = () => document.documentElement.hasAttribute("dark")`).
6. Блокировки в main_world — ТОЛЬКО в dark-режиме и ТОЛЬКО на `<html>` (не на masthead!).

### 4. Ключевые особенности реализации (грабли)

- **ISOLATED/MAIN граница миров**: `CustomEvent` c detail НЕ пересекает границу.
  content.js не может сам диспатчить yt-action с данными → ставит метку
  `data-ma-notify` на `<html>`, main_world.js MutationObserver-ом её ловит и диспатчит
  НАСТОЯЩЕЕ `yt-action` (bubbles+composed). Без этого компоненты YouTube не узнают
  о смене темы.
- **attrGuard** (content.js): МутацияObserver на атрибуты `dark`/`light` `<html>`.
  dark → держим пару; light → если YouTube сам включил dark (родной тумблер),
  синхронизируем `chrome.storage` (следим за пользователем).
- **bodyGuard**: YouTube может удалить наш тумблер из DOM → пересоздаём при childList-мутации.
- **f6 кука**: YouTube перезаписывает PREF после переключения → в dark-режиме
  перехват `document.cookie` setter в main_world держит `f6=400` в любом PREF.
- **`ytd-masthead[is-watch-page][dark]`** — селектор прозрачной шапки на
  watch-страницах. Снятие атрибута dark в light корректно включает нативные стили.
- **sessionStorage 'maTheme'** — мгновенное применение при SPA/boot до ответа storage,
  избегает «тёмной вспышки» при старте.
- **`--load-extension` работает ТОЛЬКО в chromium** (google-chrome stable ≥136 блокирует).
- **Ядро CDP-запуска**: `setsid nohup … & disown`, иначе гибнет при килле группы;
  pkill-паттерн с брекетом `user-data-dir=/tmp/ma_test_pr[o]f` (иначе килляешь сам
  bash); websocket с `--remote-allow-origins=*` и ОДНОПОТОЧНОЙ обработкой (два треда
  на один ws = ответ уходит в другой тред).

### 5. Как исследовать баг, если он вернётся (чек-лист)

1. Прочитать ДАМП реального DOM поиска (какие из 9 `*Dark` классов висят, где,
   есть ли атрибут dark на `ytd-masthead` и `<html>`).
2. Проверить CSS селекторы в актуальном `kevlar_base.css`: `[dark]`, `html[dark]`,
   `:root`, значения `--ytd-searchbox-*` — билд YouTube меняется, токены/селекторы
   плавают.
3. Проверить `f6` в куке (первый символ) и атрибуты html/masthead.
4. Проверить, что main_world блокирует ТОЛЬКО html и ТОЛЬКО в dark.
5. ВАЖНО: не удалять классовый синк целиком и не добавлять debounce — это
   регрессии Сессий 4–5. Искать дисбаланс между АТРИБУТОМ и классом masthead.
6. Сравнить с оригиналом (ImprovedTube themes.js — источник истины по мех-ке).
7. Проверить `node --check` + перезагрузить расширение и страницу (старые версии
   скриптов висят в уже открытых вкладках!).

## Сессия 8: «Чёрный чипс "Все" на главной» — это НАТИВНЫЙ YouTube

### Репорт пользователя
После переключения на светлую тему на главной странице чипс «Все»
(`yt-chip-cloud-chip-renderer`, `iron-selected`, класс `ytChipShapeActive`)
остаётся чёрным. Пользователь предложил: при светлой теме полностью
«выключить» расширение (YouTube дефолтный, как был изначально), оставить
только кнопку тумблера; обновить манифест, чтобы расширение не отключалось.

### Расследование (CDP + CSS)
1. **CSS токены активного чипса** (kevlar_base.css):
   - `.ytChipShapeActive{background-color:var(--t1405e70a39276293);color:var(--t6216186c28b3834b)}`
   - `--t1405e70a39276293` (фон активной «пилюли»): `:root` → `#0f0f0f`,
     `html[light]` → `#0f0f0f`, `[dark]` → `#f1f1f1`
   - `--t6216186c28b3834b` (текст активной) : `#f1f1f1`/`#fff` в светлой,
     `#0f0f0f` в `[dark]`
   - Redesign-вариант `--tc87f6a7f05e65fc4`: `rgba(0,0,0,0.1)` светлая /
     `rgba(255,255,255,0.1)` тёмная
   → **Активный чипс в светлой теме НАЦИОНАЛЬНО чёрный** (`#0f0f0f` на белом),
     в тёмной теме он белый (`#f1f1f1`). Это инвертированная «пилюля» YouTube,
     НЕ остаток нашего форса. Снятие dark/light это не меняет — так устроена
     тема YouTube.
2. **Нативный light** (fairborn, ПРОФИЛЬ БЕЗ расширения, f6=80000):
   `<html>` имеет `darker-dark-theme`, `darker-dark-theme-deprecate`,
   `system-icons` — и **НИКАКОГО** атрибута `dark`/`light`! Нативный YouTube
   светлый = просто отсутствие `dark`. Наш `light=""` — страховка от
   токенов с тёмным дефолтом в `:root`, см. Сессию 3.
3. **Попиксельное сравнение скриншотов** (`/tmp/ma_shot_native_light.png` vs
   `/tmp/ma_shot2_light.png`): нативный-light и расширение-light идентичны
   в полосе чипсов (y=60-140) и по всей странице (разница 0.04% = только
   спрайт нашего тумблера). Расширение в светлой теме = YouTube как был
   изначально, БЕЗ изменений.

### Вывод
- Чёрный активный чипс в светлой теме — **нативная функция дизайна YouTube**,
  чинить CSS/атрибутами не нужно. Если пользователь всё равно хочет «светлую
  пилюлю» — это уже отход от нативного вида, отдельный запрос.
- Требование «light = расширение выключено, YouTube дефолтный, только кнопка»
  **уже выполнено**: в light styles.css не содержит ни одного правила,
  main_world ничего не блокирует, content.js только ставит пару нативных
  атрибутов (light=""/снять dark) + кук f6=80000 + чистит застрявшие
  `*Dark` классы поиска + держит кнопку-тумблер.
- **Манифест менять НЕ нужно**: MV3-расширение не может «отключаться» по
  теме — content-скрипты (MAIN + ISOLATED) всегда инжектятся на
  `https://www.youtube.com/*` независимо от темы; «выключение» в light —
  это философия НАШЕГО кода (ноль правил), а не жизни расширения.
- Пользователю нужен чек-лист: перезагрузить расширение в
  chrome://extensions, перезагрузить страницу YouTube (старые скрипты висят
  в уже открытых вкладках), проверить оба направления dark→light и
  light→dark (поиск + чипсы + masthead).
