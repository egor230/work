# Как работает Magic Actions for YouTube (custom)

Пошаговое объяснение, как устроено переключение светлой/тёмной темы и почему
возникали баги. Все находки получены разбором реальных бандлов YouTube
(HTML + CSS 2.9 МБ + JS 10.7 МБ, скачанных без браузера) и CDP-диагностикой
в тестовом Chromium.

---

## 0. Главный принцип (философия v3)

**Светлая тема = «расширение выключено».**

YouTube сам умеет рендерить идеальную светлую тему: все цвета живут в
обфусцированных токенах `--t*`, определённых на `html[light]` самим YouTube.
Каждая наша попытка «помочь» светлой теме (CSS-переменные, хардкоды,
страховки) ломала нативный вид («вся белая полоска поиска», «слишком белая
страница»). Поэтому:

- **light**: ставим только нативную пару атрибутов (`light=""`, снять
  `dark`) + кук `f6=80000` + счищаем застрявшие тёмные классы у поиска.
  Дальше YouTube красит ВСЁ сам. Никаких CSS-правил для светлой темы
  вообще (в styles.css — ноль), никаких блокировок атрибутов, куки не
  патчим. Если пользователь переключил тему родным тумблером YouTube —
  расширение следует за ним (attrGuard в content.js).
- **dark**: расширение «включено» — ставим `dark=""`, кук `f6=400`,
  держим атрибуты блокировками (main_world.js), красим тёмные токены
  `--yt-spec-*`/`--yt-sys-color-baseline--*` (стили оригинального Magic
  Actions), перехватываем PREF от перезаписи.

Вторая причина такой архитектуры — тёмная тема у YouTube «достаётся»
переключением, а светлая — его естественное состояние, которое мы раньше
ломали своим вмешательством.

---

## 1. Из чего состоит расширение

| Файл | World | Задача |
|---|---|---|
| `content.js` | ISOLATED | Ядро: чтение/применение темы, тумблер, синхронизация вкладок, слежение за родным тумблером YT |
| `main_world.js` | MAIN | Работает В КОНТЕКСТЕ СТРАНИЦЫ: блокировки атрибутов (только dark-режим), перехват PREF (только dark), диспетч экшенов YT |
| `styles.css` | ISOLATED (CSS) | Тумблер + ТОЛЬКО тёмная тема. Для светлой — ни одного правила |
| `popup.html/js` | — | Кнопка в popup → пишет в `chrome.storage.local` |

Оба скрипта инжектятся на `document_start` (manifest.json), поэтому успевают
перехватить страницу до того, как YouTube начнёт рендериться.

**Зачем два мира.** ISOLATED-скрипт видит DOM, но его объекты недоступны
странице (и наоборот). MAIN-скрипт — это «как если бы сам YouTube выполнил
код»: может патчить прототипы, перехватывать куки, диспатчить события,
которые поймут YT-компоненты.

## 2. Как YouTube хранит тему (3 механизма)

### 2.1 Кук PREF, параметр f6

```
f6=400    → тёмная
f6=80000  → светлая
```

**Подвох №1: склейка флагов.** f6 — битовая маска: бит 165 (1<<10 = 0x400)
= dark, бит 174 (1<<19 = 0x80000) = light. YouTube пишет несколько флагов
одним значением, реально встречаются `40080000`, `40000400`. Поэтому читать
надо по первому символу (`4…` → dark, `8…` → light), а не точным сравнением.
Эта логика зашита в YT-бандле (`_.Xl` — setFlag: `f6 = 1 << (flag % 31)`).

**Подвох №2: YouTube сам перезаписывает PREF.** После любого внутреннего
обновления настроек YT пишет свой PREF со СВОИМ f6 → после перезагрузки
сервер рендерил старую тему. В dark-режиме решает перехват setter
`document.cookie` в main_world.js (в любом записываемом `PREF=…` ставим
f6=400). В light-режиме НЕ перехватываем — YouTube волен писать что хочет
(после установки f6=80000 при переключении YT обычно согласован).

### 2.2 Атрибуты <html>: dark и light

```css
html[dark]  { --t3e41d7b17b187f69: #0f0f0f; ... }   /* 117 обфусцированных токенов */
html[light] { --t3e41d7b17b187f69: #fff;    ... }
:root       { --t3e41d7b17b187f69: #0f0f0f; ... }   /* ДЕФОЛТ ТЁМНЫЙ! */
```

**Главный подвох всего проекта.** Современный (2025+) CSS YouTube хранит
цвета не в понятных `--yt-spec-*`, а в обфусцированных токенах `--t*`
(напр. `--t3e41d7b17b187f69` — фон страницы, `--t518e925f61bdcb91` —
панели, `--t7f4f2c6d54836ce0` — плашка поиска, `--tffc2fd3a644f6275` —
текст). Определены они на селекторах `html[dark]`/`html[light]`, а в
`:root` — **тёмный дефолт**.

Следствие: если просто снять `dark`, страница остаётся чёрной (срабатывает
тёмный `:root`). Симптом знакомый — «переключается только прокрутка»
(scrollbar-color — единственное наше прямое правило). Поэтому при светлой
теме нужно **ставить `light=""`**. `applyTheme()` управляет парой атрибутов
симметрично: dark-тема → `dark` ставим/`light` снимаем, light-тема →
наоборот.

**Защита от YT — только в dark-режиме.** В dark main_world.js патчит
`setAttribute`/`removeAttribute`/`toggleAttribute`: на `<html>` попытки
снять `dark` или поставить `light` блокируются. В light-режиме патчи
пассивны — YouTube сам управляет темой, а attrGuard в content.js просто
следит: если родной тумблер YT поставил `dark` → синхронизируем
`chrome.storage` (расширение «понимает», что пользователь выбрал тёмную).

### 2.3 Классы *Dark у компонентов (строка поиска!)

Компонент поиска `yt-searchbox` красится НЕ только токенами. При рендере
его JS вызывает:

```js
// k6 = v.forceDarkMode?.() || !!yo()
// yo() = DI-провайдер _.TP(_.g6), где g6 = new _.Xc("DARK_THEME_TOKEN"),
// его значение: SLo = () => document.documentElement.hasAttribute("dark")
```

То есть **при каждом рендере** кнопка/поле получают классы
`ytSearchboxComponentSearchButtonDark`, `ytSearchboxComponentInputBoxDark`,
`ytSearchboxComponentHostDark`, если на момент рендера на `<html>` был
`dark`. Эти классы красят **хардкод-цветами**:

```css
.ytSearchboxComponentInputBoxDark    { background-color: hsl(0,0%,7%); border-color: hsl(0,0%,18.82%); }
.ytSearchboxComponentSearchButtonDark{ background-color: hsla(0,0%,100%,.08); border: 1px solid hsl(0,0%,18.82%); }
.ytSearchboxComponentHostDark        { color: #fff }  /* !!!! */
```

**Подвох №1: компонент НЕ следит за атрибутом dark** — перерисовывается
только получив экшен `yt-dark-mode-toggled-action` (см. 2.4).

**Подвох №2: у HostDark захардкожен `color:#fff`, а все иконки YouTube
красятся через `fill: currentcolor`** (`yt-icon { fill:
var(--iron-icon-fill-color, currentcolor) }`) → иконки наследуют цвет
хоста. Поэтому любая наша перекраска фона без перекраски `color` = белые
иконки на светлом фоне — «полоска вся белая, нечитаемая».

**Подвох №3 (зеркальный баг):** застревание работает В ОБЕ СТОРОНЫ.
Базовые классы поиска красятся светлыми хардкодами/токенами
(старый UI: `SearchButton {background:#f8f8f8}`), а тёмные цвета — только
в классах `*Dark`. Если рендер произошёл в light, а потом мы включили
dark — атрибуты сменились, но классов `*Dark` нет → **кнопка поиска
остаётся светлой в тёмной теме**. Симметрично dark→light: классы `*Dark`
висят → тёмный поиск в светлой теме.

**Решение v3 (без CSS-хаков):** при каждом переключении — приводить
классы к новой теме вручную (`syncSearchboxClasses(theme)`, с повторами
на 0/300/1200 мс, YT может ре-рендерить в процессе):
- **→ dark**: ДОСТАВИТЬ классы `*Dark` на элементы поиска (querySelectorAll
  по базовым классам `ytSearchboxComponentHost/InputBox/SearchButton/
  SuggestionsContainer` → add `…Dark`) + добавить класс `dark` на
  `ytd-masthead` (у YT есть правило `ytd-masthead.shell.dark { background:
  #0f0f0f !important }`, класс ставит его собственный JS через
  `setMastheadTheme`, который вызывается только при смене page-type);
- **→ light**: СНЯТЬ классы `*Dark` и `dark` у masthead.
После синхронизации всё красится хардкодами/токенами YouTube как при
нативном рендере в нужной теме. В `applyTheme` вызывается для обоих
направлений (регресс v3.0: чистка была только для light — тёмная тема
получала светлую кнопку поиска).

### 2.4 Как YT-тумблер уведомляет компоненты: экшен yt-dark-mode-toggled-action

Из бандла (класс `D3`, ytd-toggle-theme-compact-link-renderer):

```js
onThemeSelected(dark, light) {
  _.Xl(0, 165, dark);       // флаг 165 -> бит f6 (0x400)
  _.Xl(0, 174, light);      // флаг 174 -> бит f6 (0x80000)
  this.prefs.save();
  _.x8(this.hostElement, "yt-dark-mode-toggled-action", [isDark]);
}
```

`_.x8` диспатчит **CustomEvent('yt-action')** на элементе, где
`detail = {actionName, optionalAction, args, returnValue}` (объект NIV).
Его ловит `ytd-app` (слушатель на `document.body`, поведение
YtActionRouterBehavior: `onYtAction_: e => actionRouter.handleAction(e.detail)`),
роутер `_.RD` по `actionRoutingMap` раздаёт экшен всем компонентам с
`actionMap = {"yt-dark-mode-toggled-action": "onDarkModeToggledAction"}`
— они обновляют `isDarkTheme` и перерисовываются.

**Реализация в расширении:** content.js после смены темы ставит метку
`data-ma-notify="dark|light"` на `<html>`; MutationObserver в main_world.js
видит метку и диспатчит в MAIN world настоящий
`CustomEvent('yt-action', {detail: {actionName:
'yt-dark-mode-toggled-action', args: [isDark], …}})`. Из ISOLATED world
это делать бесполезно — **объекты CustomEvent.detail не пересекают
границу миров** (YT-слушатель увидел бы null), поэтому диспатчит именно
main_world.js.

## 3. Поток данных при переключении

```
Клик по тумблеру #__magic-theme-switch (или popup-кнопке)
  └─ chrome.storage.local.set({maTheme: 'dark'|'light'})
       └─ chrome.storage.onChanged срабатывает в КАЖДОЙ вкладке YouTube
            └─ applyTheme(theme):
                 ├─ html.setAttribute('data-ma-theme', …)  ← метка режима для main_world
                 ├─ ПАРА нативных атрибутов: dark ⇄ light   ← токены --t* YT
                 ├─ [light]: scrubStaleDarkClasses() — снять классы *Dark
                 │            у поиска (+повторы 300/1200 мс)
                 ├─ sessionStorage.maTheme               ← мгновенный restore при reload
                 ├─ syncCookie: PREF f6=400/80000         ← серверная тема при загрузке
                 ├─ updateToggleIcon (солнце/луна)
                 └─ data-ma-notify → main_world.js → CustomEvent('yt-action',
                        yt-dark-mode-toggled-action) → ytd-app → роутер →
                        компоненты перерисовываются (строка поиска!)
```

Применение живьём, без перезагрузки страницы.

## 4. Загрузка страницы (boot)

```
document_start:
  main_world.js — патчит прототипы (активны только при data-ma-theme=dark),
                  перехват cookie (только dark), слушает data-ma-notify
  content.js:
    1. applyTheme(sessionStorage.maTheme || тема из PREF-куки) — МГНОВЕННО,
       до ответа chrome.storage (чтобы не было тёмной вспышки)
    2. chrome.storage.get → если расходится с куки — поправить;
       если storage пуст — инициализировать текущим значением
    3. attrGuard: MutationObserver на <html> (dark/light):
       - dark-режим: YT снял dark → вернуть
       - light-режим: появился dark → пользователь щёлкнул РОДНОЙ тумблер
         YT → синхронизировать chrome.storage (следуем за YouTube)
    4. bodyGuard: тумблер пропал из body → пересоздать
```

Фолбэк `getThemeFromCookie`: нет `PREF` → смотрим атрибут `dark` на `<html>`
(как отрендерил сервер). Ранние версии слепо считали «нет куки = светлая» —
получали конфликт с реальным рендером.

## 5. Грабли, на которых мы поймали реальные баги

1. **f6=8 вместо 80000** — YT не распознавал значение.
2. **Точное сравнение f6==='400'** — ломалось на склеенных `40080000`.
3. **location.reload() на каждый toggle** — перезапуск видео; тема теперь
   применяется живьём.
4. **Снять dark, не поставив light** — тёмный дефолт `:root` у токенов
   `--t*` → «переключается только прокрутка». Главное открытие проекта.
5. **Не заблокирован toggleAttribute('dark')** — YT обходил патч.
6. **normalize() терял 'light'** — выбор пользователя перезаписывался кукой
   после перезагрузки.
7. **YT перезаписывает PREF (f6)** — перехват cookie-setter в main_world
   (теперь только в dark-режиме).
8. **Классы __ytnight/__ytday стирались** при SPA-миграциях — теперь этих
   классов нет вообще (тема = нативные атрибуты), attrGuard держит пару.
9. **z-index тумблера 3646 = z-index диалогов YT** — клики по кнопке
   перехватывал баннер. Поставлен максимальный 2147483647 + capture.
10. **Строка поиска не перерисовывается** — классы *Dark ставятся при
    рендере и не следят за атрибутами; нужен экшен yt-dark-mode-toggled-action
    + чистка классов. Метка `data-ma-notify` и диспетч живут в main_world,
    потому что CustomEvent.detail не пересекает границу миров.
11. **Хардкод-цвета в страховке → «полоска вся белая»** — иконки YT красятся
    `fill: currentcolor` и наследовали белый `color:#fff` от HostDark; на
    перекрашенном фоне иконки/текст исчезали. Лечение v3: НЕ перекрашивать
    вообще — чистить классы *Dark и давать YouTube красить самому.
12. **CSS-переменные в светлой теме → «слишком белая страница»** — наши
    `--yt-spec-*: #fff !important` перекрывали нативные значения YouTube
    (местами полупрозрачные плашки). Лечение v3: в светлой теме НОЛЬ наших
    правил — светлая = «расширение выключено».
13. **Регресс v3.0 «тумблер исчез»** — при полном переписывании styles.css
    base64-спрайт кнопки обрезался (line truncation при чтении файла
    инструментом → вставился неполный PNG, decode падал). Урок: длинные
    data-URI переносить программно (replace по regexp между файлами),
    а не через чтение глазами. Проверка целостности: base64.b64decode
    + PNG-магия `89504e47…`.
14. **Регресс v3.0 «кнопка поиска светлая в тёмной теме»** — чистку классов
    сделали только для light-направления, забыли зеркальное: базовые
    классы поиска красятся СВЕТЛЫМИ хардкодами (#f8f8f8), тёмные — только
    в классах *Dark. Урок: застревание симметрично — при каждом
    переключении приводить классы к НОВОЙ теме (dark→доставить *Dark,
    light→снять), не только снимать старые.
15. **Токен может быть перебит блоком с большей специфичностью** — активная
    «пилюля» чипов (`ytChipShapeActive`) красится токенами
    `--t1405e70a39276293` (фон) / `--t6216186c28b3834b` (текст). В `[dark]`
    текст должен быть `#0f0f0f`, но YouTube в этом билде добавил блок
    `:root:root` (двойной `:root`, specificity (0,2,0) > у `[dark]` (0,1,0)),
    задающий `--t6216186c28b3834b:#f1f1f1` → белый текст на белой пилюле,
    чип нечитаем. Лечение: `html[dark] .ytChipShapeActive { color: #0f0f0f }`.
    Диагностика: читать РЕЗОЛЬВНУТЫЕ значения через `getComputedStyle`, а не
    grep-значения из `[dark]`-блока (они врут, если есть более сильный селектор).

## 6. Диагностика без/с браузером

- **Без браузера**: `curl` главную страницу с кукой `PREF=f6=80000` → из
  HTML вытащить ссылки на CSS/JS бандлы (`/s/_/ytmainappweb/_/ss/…` — CSS,
  `/s/_/ytmainappweb/_/js/…` — JS) → grep/regex по ним. Сервер отдаёт
  `<html>` без dark/light — их ставит JS на клиенте. Файлы исследования
  оседали в `/tmp/ma_research/` (home.html, main.css, main.js).
- **CDP (если нужен живой тест)**: только `chromium` (в google-chrome
  stable ≥136 флаг `--load-extension` заблокирован!); запуск
  `setsid nohup … & disown` (иначе процесс гибнет при килле группы);
  pkill-паттерн с брекетом: `pgrep -f "user-data-dir=/tmp/ma_test_pr[o]f"`
  (без брекета pkill убивает сам bash-инструмент). Trusted-клик —
  `Input.dispatchMouseEvent` по координатам `getBoundingClientRect()`.
  Поиск красящего правила — `DOM.enable` + `CSS.enable` +
  `CSS.getMatchedStylesForNode` (атрибутов и inline-стилей нет — всё в
  токенах). Признак здоровья: `--t3e41d7b17b187f69` = #fff (light) /
  #0f0f0f (dark), и ytd-app следует за html.

## 7. Признак полностью рабочей темы

- фон страницы, шапка, гайд, карточки, текст — всё одной темы (html и
  ytd-app одинаковы);
- **строка поиска**: поле, кнопка справа, иконки — выглядят ровно как
  нативные (никаких «белых полос» и тёмных остатков), проверяется после
  ЖИВОГО переключения без reload;
- светлая тема неотличима от «расширения выключено» — потому что в ней
  расширение и выключено;
- после F5 тема сохраняется (кука f6 + storage согласованы);
- щелчок по родному тумблеру YouTube подхватывается расширением;
- тема едина во всех вкладках YouTube.
