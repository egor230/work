# Magic Actions for YouTube — разбор проблем и ошибок

## Задача

Разработать кастомное расширение для Chrome (Manifest V3), которое позволяет
переключать светлую и тёмную тему на YouTube. Расширение должно работать
надёжно: не ломать визуал страницы, не вызывать циклы перезагрузок,
корректно синхронизироваться со встроенными механизмами YouTube.

Исходный код — урезанная копия коммерческого расширения "Magic Actions for
YouTube" (Mixesoft, v7.9.5.6), из которой оставлена только функция
переключения темы. Остальные файлы оригинала (esw30.js, gjs30/, gcss30/,
e*.html) лежат как мёртвый груз и не подключены.

---

## Хронология проблем

### раунд 1: первая реализация

**Что было сделано:**
- content.js читал тему из куки PREF (параметр `f6=400` → dark, иначе light)
- `syncCookie()` записывал `f6=8` для светлой темы
- После каждого переключения вызывался `location.reload()`
- main_world.js блокировал только `setAttribute`/`removeAttribute` для `dark`
- Классы `__ytnight`/`__ytday` ставились на `<html>`

**Обнаруженные ошибки:**

#### Ошибка 1: Неверное значение куки для светлой темы
Кастом записывал `f6=8`, а YouTube и оригинальное расширение используют
`f6=80000`. Оригинальный код из `gjs30/ewatch30.js`:
```js
k.set("f6", fb ? "400" : "80000")
```
Сервер YouTube мог не распознавать `8` как валидное значение, поэтому
после перезагрузки тема откатывалась.

#### Ошибка 2: Хрупкое чтение темы из куки
Точное сравнение `f6 === '400'` ломалось на склеенных значениях флагов.
YouTube — битовая маска: бит 165 = `0x400` (dark), бит 174 = `0x80000`
(light). Реально встречаются значения вида `40080000`, `40000400`. При
склейке `f6 === '400'` не матчится → тема читалась как "светлая".

#### Ошибка 3: Отсутствие куки PREF = слепо "светлая"
Если куки `PREF` нет (чистый профиль, не-залогиненный), код считал
тему светлой. Но сервер мог отрендерить `<html dark>` → расхождение при
каждом заходе.

#### Ошибка 4: location.reload() после каждого toggle
После каждого переключения — полная перезагрузка страницы. Видео
перезапускалось. При рассинхроне хранилища и куки (залогиненные
пользователи: сервер сам ставит PREF по теме аккаунта) — цикл
перезагрузок при каждом открытии.

#### Ошибка 5: toggleAttribute('dark') не блокировался
YouTube меняет тему не только через `setAttribute`/`removeAttribute`,
но и через `toggleAttribute('dark')`. Оригинальный патч main_world.js
этот метод не перехватывал → YouTube обходил блокировку → нативные
тёмные стили включались поверх форсированных CSS-переменных →
**смешанная тема** (главный визуальный баг).

---

### раунд 2: после первого набора исправлений

**Что было исправлено:**
- Запись куки: `f6=400`/`f6=80000` (как в оригинале)
- Чтение по префиксу: `f6.charAt(0) === '4'` → dark
- Убран `location.reload()` — тема применяется живьём
- Заблокирован `toggleAttribute('dark')` в main_world.js
- Добавлен `MutationObserver` для восстановления классов

**Ответ пользователя:** "переключатель не работает, только
переключается с чёрного на белый — это прокрутка, а всё остальное
не переключается"

---

### раунд 3: CDP-диагностика

Запущен тестовый Chromium с расширением, открыт YouTube. Через CDP
проверялось:
- Состояние атрибутов `<html>` до/после toggle
- Значения CSS-переменных `--t*` и `--yt-spec-*`
- Классы компонентов (особенно строка поиска)

**Ключевое открытие:** цвета страницы YouTube живут НЕ в `--yt-spec-*`
переменных (которые мы переопределяли), а в **обфусцированных токенах
`--t*`** (например `--t3e41d7b17b187f69` — фон страницы). Определены
они на `html[dark]`/`html[light]`, а в `:root` — **тёмный дефолт**.

Следствие: просто снять атрибут `dark` = страница остаётся чёрной
(срабатывает тёмный `:root`). Симптом — «переключается только
прокрутка» (единственное наше прямое CSS-правило `scrollbar-color`).

## Почему задачу не удалось решить с первого раза

### Корневая причина: непонимание архитектуры темы YouTube

Современный YouTube (2025+) хранит цвета в трёх независимых местах:

1. **Кук PREF (f6)** — серверный флаг темы, применяется при загрузке
2. **Атрибуты `<html>`: `dark`/`light`** — управляет обфусцированными
   CSS-токенами `--t*` (117+ переменных на каждый селектор)
3. **Классы компонентов** (например `*Dark` у строки поиска) — ставятся
   при рендере и НЕ следят за атрибутами

Первая реализация работала только с первым механизмом (куки) и частично
со вторым (атрибуты). Третий механизм (классы компонентов) не учитывался
вовсе.

### Дополнительная сложность: два мира JavaScript

Chrome extensions MV3 работают в двух изолированных JS-мирах:
- **ISOLATED** (content.js) — видит DOM, но его объекты не доступны странице
- **MAIN** (main_world.js) — работает в контексте страницы, может
  патчить прототипы и диспатчить события, которые поймут компоненты YT

Многие операции (патчинг прототипов, диспетч `CustomEvent` с `detail`,
перехват cookie-setter) требуют MAIN world. Ошибки в определении того,
в каком мире выполнять ту или иную операцию, приводили к тому, что
YouTube "обходил" блокировки.

## Неверные решения и их последствия

### 1. "`f6=8` — нормальное значение для светлой темы"
**Почему неверно:** YouTube использует `f6=80000` (бит 174 = 0x80000).
Значение `8` не распознаётся сервером → после перезагрузки тема
откатывается. Нашли, сравнив с оригинальным кодом из `ewatch30.js`.

### 2. "`location.reload()` — надёжный способ применить тему"
**Почему неверно:** YouTube — SPA, видео перезапускается. У
залогиненных пользователей сервер перезаписывает PREF под тему аккаунта
→ расхождение storage/куки → бесконечный цикл reload. Оригинальное
расширение применяет тему живьём.

### 3. "Патчим setAttribute/removeAttribute — этого достаточно"
**Почему неверно:** YouTube использует также `toggleAttribute('dark')`
и, возможно, другие пути. Достаточно одного незаблокированного — и
YouTube включает нативные стили поверх.

### 4. "`__ytnight`/`__ytday` классы — основа темы"
**Почему неверно:** YouTube периодически перезаписывает `className`
у `<html>` при SPA-миграциях, снося наши классы. CSS-переменные
`--yt-spec-*`, которые мы переопределяли под этими классами,
отваливались. Решение: отказаться от кастомных классов, работать
только с нативными атрибутами `dark`/`light`.

### 5. "Для светлой темы нужно прописать CSS-переменные"
**Почему неверно:** Наши `--yt-spec-*: #fff !important` перекрывали
нативные значения YouTube (местами полупрозрачные плашки) → «слишком
белая страница». Иконки YT красятся через `fill: currentcolor` и
наследовали белый `color:#fff` от HostDark → «полоска вся белая,
нечитаемая». Решение: в светлой теме **ноль** наших CSS-правил.

### 6. "`CustomEvent` с `detail` работает из любого контекста"
**Почему неверно:** Объект `CustomEvent.detail` **не пересекает
границу** ISOLATED → MAIN миров. Если dispatch делать из ISOLATED
(content.js), YT-слушатель на `ytd-app` получает `null` → экшен
не обрабатывается → строка поиска и другие компоненты не
перерисовываются. Диспетч必須 в MAIN world.

### 7. "Чистка классов *Dark нужна только при dark→light"
**Почему неверно:** Застревание симметрично. Базовые классы поиска
красятся светлыми хардкодами (`#f8f8f8`), тёмные цвета — только в
классах `*Dark`. Если рендер был в light, а потом включили dark —
классов `*Dark` нет → кнопка поиска остаётся светлой в тёмной теме.
Нужно **при каждом переключении** приводить классы к новой теме.

### 8. "Base64-спрайт можно переносить через чтение файла"
**Почему неверно:** При полном переписывании styles.css base64-спрайт
кнопки (2320 символов) обрезался при line truncation в инструменте
чтения → PNG сломан → кнопка невидима. Длинные data-URI нужно
переносить программно (regexp replace между файлами), с проверкой
`base64.b64decode` + PNG-магия `89504e47`.

## Финальная архитектура (v3)

После всех ошибок пришли к философии: **светлая тема = "расширение
выключено"**.

- **dark**: расширение "включено" — ставим `dark=""`, кук `f6=400`,
  блокируем атрибуты через main_world.js, красим тёмные токены
  `--yt-spec-*`/`--yt-sys-color-baseline--*`, перехватываем PREF,
  достаём/чистим классы `*Dark` у поиска, диспатчим
  `yt-dark-mode-toggled-action`.
- **light**: расширение "выключено" — ставим только нативную пару
  атрибутов (`light=""`, снять `dark`) + кук `f6=80000` + чистим
  застрявшие классы `*Dark`. YouTube сам красит всё. В styles.css
  для light — **ноль правил**. Если пользователь переключил тему
  родным тумблером — attrGuard в content.js это видит и
  синхронизирует chrome.storage.

## Уроки

1. **Изучать的目标-систему до написания кода.** Цвета YouTube не в
   `--yt-spec-*`, а в обфусцированных `--t*` с тёмным дефолтом.
2. **Не навязывать своё в нативную систему.** Светлая тема YouTube
   работает идеально без нашего вмешательства — каждая наша
   "страховка" ломала её.
3. **Симметричность багов.** Застревание классов, конфликты атрибутов
   — работают в обе стороны. Нужно тестировать оба направления.
4. **Два мира — два контекста.** Ошибки в определении ISOLATED/MAIN
   приводят к "невидимым" багам (событие dispatch'ится, но.detail=null).
5. **E2E-тестирование через CDP** — единственный способ убедиться, что
   тема работает на реальной странице YouTube, а не только в теории.
6. **Большие data-URI** не переносить через ручное чтение/запись —
   только программно, с проверкой целостности.
