# SysBackup — руководство пользователя и администратора

**SysBackup** — утилита для резервного копирования и восстановления Linux-систем (ориентирована на Linux Mint и Manjaro, но применима и к совместимым дистрибутивам) с графическим интерфейсом (GTK) и консольным режимом (CLI), включая headless-работу по сети.

Документ описывает возможности программы, состав бэкапа, требования, установку/запуск, сценарии использования, сетевой режим, диагностику и ограничения.

---

## 1. Назначение и возможности

SysBackup помогает:
- создавать резервную копию ключевых компонентов системы в выбранную папку (локальную или на смонтированном сетевом хранилище);
- восстанавливать систему из ранее созданной резервной копии;
- упростить выполнение операций через `sudo` (опционально, настройка `NOPASSWD` для текущего пользователя);
- выполнять операции без GUI и удалённо по сети (режим сервера/клиента).

### Основные функции
- **GUI** (`sysbackup-gui` / AppImage без аргументов): кнопки для настройки sudo, создания бэкапа и восстановления.
- **CLI** (`sysbackup-cli` / AppImage с командами): автоматизация и работа в терминале/по SSH.
- **Сетевой режим**: запуск сервера SysBackup на целевой машине и удалённый запуск операций с клиентской машины.
- **Логирование**: подробный лог действий и ошибок.
- **Проверка окружения/бэкапа**: команда `check`.

## 3. Что входит в резервную копию

Бэкап создаётся в выбранной папке в виде обычных файлов/каталогов (без упаковки в единый архив).

```text
<backup_dir>/
├── packages/
│   ├── apt_packages.list        # Список установленных APT-пакетов (dpkg --get-selections)
│   ├── apt_repos/               # /etc/apt/sources.list и /etc/apt/sources.list.d/
│   ├── apt_cache/               # .deb пакеты из /var/cache/apt/archives/ (+ попытка догрузки/клонирования)
│   ├── apt-clone.tar.gz         # (опционально, если доступен apt-clone и клонирование успешно)
│   ├── flatpak_list.txt         # Список Flatpak-приложений (flatpak list --app --columns=ref)
│   ├── flatpak_apps/            # Офлайн-копия Flatpak (create-usb/репозиторий или .flatpak bundle)
│   ├── snap_list.txt            # Список Snap-пакетов
│   └── snap_apps/               # Скачанные .snap и .assert (snap download)
├── system_configs/
│   └── etc/                     # Полная копия /etc (rsync -aAXH --numeric-ids)
├── user_data/
│   └── home/                    # Копия домашней директории пользователя, включая скрытые файлы
│                                # (по умолчанию исключается ~/.cache)
├── backup_info.json             # Метаданные: дата, пользователь, сведения об ОС, исключения
└── backup_status.json           # Статус/этап выполнения (для диагностики)
```

### Что копируется и чем
- **APT (Debian/Ubuntu/Mint):** список пакетов, источники репозиториев, локальный кэш `.deb`; при наличии `apt-clone` выполняется попытка клонирования состояния.
- **Flatpak (если установлен):** список приложений и попытка офлайн-экспорта (`flatpak create-usb`, при ошибке — `flatpak build-bundle` где возможно).
- **Snap (если установлен):** список и скачивание пакетов (`snap download`) для последующей офлайн-установки.
- **Системные конфиги:** `/etc`.
- **Данные пользователя:** домашняя директория текущего (реального) пользователя, включая dotfiles (`.config`, `.local` и т.д.), с исключением `.cache` по умолчанию.

> Отсутствующие менеджеры пакетов/утилиты (например, `flatpak` или `snap`) автоматически пропускаются с записью в лог.

## 4. Что делает восстановление

При восстановлении (на машине, где запущен SysBackup):
1. Проверяется окружение и структура папки бэкапа.
2. Восстанавливаются источники APT и устанавливаются пакеты из локального кэша `.deb` (best-effort), при наличии применяется `apt_packages.list` (`dpkg --set-selections`).
3. Восстанавливаются Flatpak/Snap из офлайн-данных бэкапа (если доступны).
4. Восстанавливается `/etc` из `system_configs/etc`.
5. Восстанавливается домашняя директория из `user_data/home` в домашний каталог текущего (реального) пользователя; выполняется попытка вернуть владельца файлов (`chown -R`).

> **Важно:** восстановление — операция высокого риска (перезапись конфигураций, установка/изменение пакетов, замена пользовательских файлов). Рекомендуется выполнять его на совместимой системе (желательно свежеустановленной/тестовой) и понимать возможные последствия.

## 5. Требования

### 5.1 Системные требования (для создания/восстановления бэкапа)
- ОС Linux (тестовые целевые сценарии: Linux Mint, Manjaro; возможна работа на совместимых дистрибутивах)
- Права администратора (`root`/`sudo`) для операций бэкапа и восстановления
- Обязательные утилиты: `sudo`, `rsync`
- Для APT-сценариев: `dpkg`, `apt-get` (и желательно `apt-cache`)
- Опционально: `flatpak`, `snap`, `apt-clone`, `visudo`

### 5.2 Требования для исходной версии (GUI/CLI из папки проекта)
- Python 3
- Для GUI: PyGObject (GTK 3)
  - Linux Mint / Ubuntu / Debian: `python3-gi`, `gir1.2-gtk-3.0`
  - Manjaro / Arch: `python`, `python-gobject`, `gtk3`

### 5.3 Требования для AppImage
- Архитектура: `x86_64`
- Совместимость системных библиотек (в первую очередь glibc) с окружением сборки
- Для GUI в AppImage: системные библиотеки/typelib’ы GTK/GI (PyGObject runtime в системе)
- Для CLI/headless: GTK не требуется

### 5.4 Место на диске и доступ
- Достаточно свободного места в папке назначения бэкапа (зависит от размера `/home`, `/etc`, кэша пакетов и т.д.)
- Доступ на чтение к исходным данным и на запись в папку бэкапа/целевые пути при восстановлении
- Для сетевых путей — корректно смонтированное хранилище (NFS/SMB/SSHFS и т.п.) или рабочий сетевой режим SysBackup

## 7. Запуск и использование

### 7.1 Графический интерфейс (GUI)

**Исходная версия:**
```bash
./sysbackup-gui
```

**AppImage:**
```bash
./SysBackup-x86_64.AppImage
```

В окне доступны действия:
- **Отключить запрос пароля (sudo)** — создаёт файл `/etc/sudoers.d/sysbackup-nopasswd` для текущего пользователя (при первом запуске может потребоваться ввод пароля sudo).
- **Создать бэкап** — выбор папки назначения и запуск резервного копирования.
- **Восстановить из бэкапа** — выбор папки бэкапа и запуск восстановления (после подтверждения).

Операции выполняются в фоне; статус и ошибки отображаются в интерфейсе, подробности — в логе.

### 7.2 Консольный интерфейс (CLI)

**Исходная версия:**
```bash
./sysbackup-cli --help
```

**AppImage (явный CLI-режим):**
```bash
./SysBackup-x86_64.AppImage --cli --help
# или напрямую командами:
./SysBackup-x86_64.AppImage --help
```

#### Основные команды
```bash
# Проверка окружения
./sysbackup-cli check

# Проверка окружения и структуры конкретного бэкапа
./sysbackup-cli check --source /path/to/backup

# Создать бэкап
./sysbackup-cli backup --dest /path/to/backup

# Восстановить из бэкапа
./sysbackup-cli restore --source /path/to/backup

# Отключить запрос пароля sudo (NOPASSWD) для текущего пользователя
./sysbackup-cli disable-sudo-password
```

> Пути могут быть локальными или находиться на смонтированных сетевых ресурсах (например, `/mnt/nas/backup`).

## 8. Работа без GUI и по сети (headless / удалённое управление)

SysBackup поддерживает встроенный сетевой режим: на целевой машине запускается сервер, который выполняет операции локально; клиентская машина отправляет команды.

### 8.1 Запуск сервера на целевой машине
```bash
# Исходная версия
./sysbackup-cli serve --host 0.0.0.0 --port 8765 --token SECRET

# AppImage
./SysBackup-x86_64.AppImage serve --host 0.0.0.0 --port 8765 --token SECRET
```

Параметры:
- `--host` — адрес прослушивания (по умолчанию `0.0.0.0`)
- `--port` — порт (по умолчанию `8765`)
- `--token` — токен доступа (рекомендуется). Также можно задать `SYSBACKUP_SERVER_TOKEN`.
- `--once` — обработать один запрос и завершиться

### 8.2 Удалённый запуск операций с клиентской машины
```bash
# Создать бэкап на удалённой машине в указанном на ней пути
./sysbackup-cli remote-backup --host <IP_СЕРВЕРА> --port 8765 --token SECRET --dest /path/on/server/backup

# Восстановить на удалённой машине из указанного на ней пути
./sysbackup-cli remote-restore --host <IP_СЕРВЕРА> --port 8765 --token SECRET --source /path/on/server/backup

# Отключить запрос sudo на удалённой машине
./sysbackup-cli remote-disable-sudo-password --host <IP_СЕРВЕРА> --port 8765 --token SECRET
```

Аналогично для AppImage (замените `./sysbackup-cli` на `./SysBackup-x86_64.AppImage`).

### 8.3 Важные особенности сетевого режима
- Пути `--dest`/`--source` интерпретируются **на стороне сервера** (целевой машины).
- Сервер выполняет привилегированные операции (через `sudo/root`) — защищайте доступ.
- Протокол обмена — простой TCP/JSON без шифрования. Используйте `--token`, ограничивайте доступ фаерволом и применяйте только в доверенной сети, VPN или через защищённый туннель (например, SSH-туннель).
- Для резервирования на NAS используйте путь к смонтированному хранилищу на сервере (например, `/mnt/nas/backup`).

## 9. Логи, диагностика и проверка

- **Файл лога:** `~/.local/share/sysbackup/sysbackup.log`
- **Проверка окружения/бэкапа:**
  ```bash
  ./sysbackup-cli check
  ./sysbackup-cli check --source /path/to/backup
  ```
- **Метаданные бэкапа:** `<backup_dir>/backup_info.json`
- **Статус выполнения:** `<backup_dir>/backup_status.json` (этапы/ошибки создания или восстановления)

Рекомендуется после создания бэкапа:
- убедиться, что команда завершилась успешно;
- проверить наличие ключевых директорий/файлов (`packages`, `system_configs/etc`, `user_data/home`, `backup_info.json`);
- просмотреть лог на предупреждения (например, пропущенные менеджеры пакетов, недоступные артефакты).

## 10. Рекомендации для надёжного бэкапа и восстановления

1. **Тестируйте восстановление заранее** на тестовой/виртуальной машине, максимально близкой к исходной системе.
2. **Закрывайте критичные приложения** перед бэкапом (браузеры, БД, редакторы), чтобы уменьшить риск несогласованных данных.
3. **Используйте отдельное хранилище** (внешний диск/смонтированный NAS), а не тот же физический диск, что и система.
4. **Проверяйте свободное место** в папке назначения до запуска.
5. **Учитывайте особенности пакетных менеджеров:**
   - офлайн-восстановление APT зависит от наличия нужных `.deb` в `apt_cache` и совместимости версий/зависимостей;
   - Flatpak/Snap офлайн-восстановление зависит от успешности экспорта/скачивания артефактов на этапе бэкапа.
6. **Для серверов/сложных конфигураций** дополняйте SysBackup специализированными бэкапами (БД, контейнеры, отдельные тома, шифрованные секреты и т.д.).
7. **После восстановления** проверьте загрузку системы, сетевые настройки, службы, права доступа и работоспособность приложений; при необходимости перезагрузите систему.

## 11. Безопасность

- Команда `disable-sudo-password` создаёт `/etc/sudoers.d/sysbackup-nopasswd` с правилом `<user> ALL=(ALL) NOPASSWD: ALL` — это **существенно снижает защиту** учетной записи. Используйте только при осознанной необходимости и удаляйте правило после завершения работ:
  ```bash
  sudo rm -f /etc/sudoers.d/sysbackup-nopasswd
  ```
- Сетевой сервер SysBackup позволяет инициировать привилегированные операции. Не публикуйте порт в интернет, используйте токен, фаервол, VPN/SSH-туннель.
- Бэкап содержит конфиденциальные данные (`/etc`, домашний каталог, ключи, токены, настройки приложений). Храните бэкапы в защищённом месте и ограничивайте доступ.

## 12. Ограничения и честные замечания о "полной совместимости"

SysBackup проектируется как практичный инструмент системного бэкапа/восстановления, но **не может гарантировать идеальную работу на любой Linux-системе во всех сценариях**. Ограничения зависят от окружения:

- **Дистрибутив и версия:** различия в пакетных менеджерах, путях, политиках, версиях пакетов и зависимостях.
- **Состояние системы:** запущенные службы, открытые файлы, базы данных, шифрованные разделы, нестандартные точки монтирования.
- **Офлайн-восстановление пакетов:** может быть неполным, если в момент бэкапа не удалось получить все необходимые артефакты/зависимости.
- **Аппаратные и драйверные различия:** восстановление на другое «железо» может потребовать ручной донастройки (загрузчик, драйверы, fstab, сеть и т.д.).
- **AppImage переносимость:** bundled Python уменьшает зависимость от Python в системе, но GUI всё равно требует системных GTK/GI компонентов, а бинарная совместимость ограничена версиями системных библиотек (например, glibc).
- **Сетевой протокол:** простой и удобный для локальной/доверенной среды, но без встроенного шифрования.

Если требуется максимальная надёжность — используйте SysBackup как часть стратегии резервного копирования (вместе со снимками файловой системы/диска, проверкой восстановления и отдельными бэкапами критичных данных).

## 13. Устранение неполадок (быстрые подсказки)

- **`rsync не найден` / `sudo не найден`** — установите недостающие пакеты (`rsync`, `sudo`) и повторите `check`.
- **GUI не запускается в AppImage** — установите GTK/PyGObject runtime в системе или используйте CLI/`serve` режим.
- **Ошибки при установке `.deb`** — проверьте наличие файлов в `packages/apt_cache`, совместимость дистрибутива/версий, лог; при необходимости выполните доустановку зависимостей вручную в целевой системе.
- **Flatpak/Snap не восстановились полностью** — проверьте, что соответствующие менеджеры установлены и что в бэкапе есть `flatpak_apps`/`snap_apps` и списки.
- **Нет доступа к сетевому пути** — убедитесь, что ресурс смонтирован и доступен на чтение/запись под нужным пользователем/root.
- **Удалённые команды зависают/обрываются** — проверьте сеть, фаервол, токен, доступность порта и лог на сервере; учитывайте длительность операций бэкапа/восстановления.

При анализе проблем всегда начинайте с `~/.local/share/sysbackup/sysbackup.log` и `backup_status.json` в папке бэкапа.

## 14. Краткая памятка команд

```bash
# Проверка
./sysbackup-cli check
./sysbackup-cli check --source /path/to/backup

# Локально
./sysbackup-cli backup --dest /path/to/backup
./sysbackup-cli restore --source /path/to/backup
./sysbackup-cli disable-sudo-password

# Сеть (сервер на целевой машине)

# Сеть (клиент)
./sysbackup-cli remote-backup  --host <IP> --port 8765 --token SECRET --dest /path/on/server/backup
./sysbackup-cli remote-restore --host <IP> --port 8765 --token SECRET --source /path/on/server/backup

# AppImage: те же команды, например
./SysBackup-x86_64.AppImage --cli check
./SysBackup-x86_64.AppImage serve --host 0.0.0.0 --port 8765 --token SECRET
```
