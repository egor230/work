# ReWASD Linux

Программа в визуальном стиле reWASD 9.3, объединяющая функциональность двух
проектов пользователя:

- **мышь и клавиатуру** — профили игр, привязки кнопок, макросы и скрипты;
- **геймпад Xbox 360** — эмуляция через `evdev/uinput`, зоны кнопок и триггеры.

Результат — компактный проект из **трёх Python-файлов** с **одним** файлом
настроек `settings.json`.

---

## 1. Состав проекта

В папке ровно три `.py`-файла:

| Файл | Роль |
|---|---|
| `ReWASD.py` | **Основной.** Точка входа, главное окно, все четыре вкладки, обработчики мыши/клавиатуры, разделители, диалоги, сохранение настроек, скриншот по F11, запуск движков |
| `library.py` | **Дополнительная библиотека.** Данные и движки: `Worker` эмуляции геймпада, `ProfileManager`, мышиный движок `MouseSettingApp` / `MouseProfileRuntime` / `SmartTyper`, функции чтения‑записи JSON, генератор команд `xte` |
| `appearance.py` | **Внешний вид.** `GamepadWidget` и 25 зон, `InteractiveMouse`, `KeyboardWidget`, `VirtualKeyboard`, темы и константы |

Остальные файлы и папки:

| Файл / папка | Назначение |
|---|---|
| `ReWASD.sh` | Единственный скрипт запуска (через venv `../../../Project/myvenv`) |

| `settings.json` | **Единственный JSON**: абсолютно все настройки программы и данные движков |
| `screenshot.png` | Пример скриншота игры для вкладки «Макросы» |
| `Screenshot_from_games/` | Сюда сохраняются скриншоты по F11 (папка создаётся автоматически) |

| `assets/window_icon.png` | Иконка окна на панели задач (256×256) |

## 2. Запуск и жизненный цикл

```bash
bash ReWASD.sh
```

Используется Python из `../../../Project/myvenv` (PyQt6, evdev, pynput,
`keyboard`, `psutil`, `deepdiff`, `mss`, Pillow). Первый запуск на этом диске
может быть долгим — это особенность файловой системы, а не программы.

Что происходит при запуске:

1. Проверяется lock-файл `/tmp/rewasd_linux_single_instance.lock`. Если программа
   уже запущена — появляется окно «Программа уже запущена» с кнопкой OK, вторая
   копия сразу завершается.
2. Загружается `settings.json`. Если в нём ещё нет разделов `mouse_data` /
   `gamepad_data`, они переносятся из старых JSON-файлов, а те удаляются.
3. Восстанавливаются положение и размер окна, размеры всех разделителей и
   колонок, профили, зоны геймпада.
4. **Скрыто поднимается мышиный движок** из исходного проекта. Его окно не
   показывается — интерфейс программы остаётся прежним.
5. **Сразу запускается эмуляция геймпада** (как в оригинальном редакторе).
6. Ставятся глобальные горячие клавиши **End**, **F3**, **F11**.
7. Окно **не показывается** — программа стартует в системный трей. Клик по
   иконке в трее или пункт «Показать окно» открывает окно; «Выход» завершает
   работу.

## 3. Горячие клавиши

| Клавиша | Действие |
|---|---|
| **F11** | Сделать скриншот всего экрана (подробнее — раздел 7) |
| **F3** | Включить/выключить режим редактирования зон геймпада |
| **End** | Остановить эмуляцию геймпада |

Клавиши глобальные — работают, даже когда окно программы скрыто в трее или в
фокусе другая программа/игра (под X11).

## 4. Устройство интерфейса

### 4.1. Верхняя панель

- **«Добавить»** — на вкладках «Мышь», «Клавиатура», «Геймпад» создаёт новый
  профиль; на вкладке «Макросы» открывает выбор файла изображения.
- **«Удалить»** — на обычных вкладках удаляет текущий профиль; на вкладке
  «Макросы» удаляет текущую координату эмблемы и сбрасывает красную рамку.
- Заголовок «SEND INPUT → GAMEPAD / MOUSE / KEYBOARD» — декоративный баннер.

### 4.2. Боковое меню

- Пункты **Мышь / Клавиатура / Геймпад / Макросы**; ширина меню меняется
  перетаскиванием границы с рабочей областью.
- Снизу — блок «Текущий профиль»: подпись и выпадающий список разделены
  movable-границей, ниже список всех профилей с перемещением ▲▼ и
  перетаскиванием, а выше — разделитель высоты блока.
- Лишнее место при изменении высоты уходит в пустоту внизу, а не растягивает
  текст.
- Двойной клик по строке профиля **или по выпадающему списку** открывает окно
  «Переименовать профиль» с полем, заполненным текущим именем.
- **«По умолчанию»** — обязательный первый профиль; восстанавливается
  автоматически, если его не было в сохранённом списке.

### 4.3. Вкладка «Мышь»

- 7 кнопок; колонки: **Кнопка мыши**, **Клавиша**, **Удерживать**, **Повторять**,
  **Время повторения**, **Скрипты**.
- «Удерживать» и «Повторять» — радиокнопки: активно только одно состояние.
- «Время повторения» — пусто / 5 / 10 / 20 секунд.
- Интерактивный рисунок мыши: скруглённое основание, боковые кнопки
  прямоугольниками, зоны колёсика и средней кнопки с правильным приоритетом.
- Подсветка двусторонняя: наведение на рисунок выделяет строку таблицы,
  наведение на строку подсвечивает кнопку на рисунке.
- Все колонки тянутся мышью; минимальная ширина рассчитывается по тексту
  заголовка, поэтому названия не обрезаются и не выходят за край.
- При смене профиля загружаются его привязки из `mouse_data.key_value`, а
  изменение привязки записывается обратно в выбранный профиль. Ячейки
  «Скрипты» перекрашиваются заново: у профиля со скриптом на боковой кнопке
  (например, `XBUTTON1`) соответствующая строка становится жёлтой.
- Скрытый движок синхронизируется с изменениями сразу: данные попадают в его
  память и пересоздаётся рантайм (`prepare`), поэтому эмуляция правой кнопки
  мыши боковой кнопкой и клавиатурные скрипты работают без перезапуска.

### 4.4. Вкладка «Клавиатура»

- Полная виртуальная клавиатура с NUM-блоком в стиле пользователя:
  фон `#302E2C`, клавиши `#383633`, золотистая граница `#A69B80`; низ подрезан
  примерно на 3%.
- Клавиатура — настоящий интерактивный виджет внутри `QGraphicsView`, поэтому
  клавиши подсвечиваются штатным жёлтым `:hover` точно по своей форме.
- Ниже — таблица соответствий действий геймпада клавишам (2 тянущиеся колонки,
  без нумерации строк). Высота клавиатуры и таблицы меняется разделителем.
- Кнопка «Полная виртуальная клавиатура» открывает отдельное окно выбора
  клавиши с тем же поведением.

### 4.5. Вкладка «Геймпад»

- Полноразмерный рисунок «Минималистичный контур Xbox-контроллера»,
  масштабируется вместе с окном (вплоть до полного экрана).
- 25 интерактивных зон, выставленных по центрам кнопок: триггеры, плечики,
  стики, D-pad, A/B/X/Y, Guide/Back/Start. Подписи зон показывают текущие
  привязки.
- Панель справа — «Назначение клавиш»; её ширина меняется разделителем.
- Кнопки «Запустить эмуляцию» / «Остановить»; эмуляция дополнительно стартует
  сама при запуске программы, как в редакторе Xbox 360.
- Под рисунком — параметры эмуляции: ползунки «Чувств. X» и «Чувств. Y» (1–15),
  флажки **«Мышь»**, **«Сглаживание»** и **«Захват клавиатуры»**. Все значения
  сохраняются в `settings.json`, а при работающей эмуляции изменение любого из
  них перезапускает поток. По умолчанию `grab: false` — физическая клавиатура
  не захватывается, набор текста в других программах работает. Раньше
  `mouse_on` и `smooth` были жёстко заданы `True`, а флаг назывался «Захват
  мыши», хотя параметр `grab` захватывает именно клавиатуру.
- Режим **«Редактировать зоны»**: кнопка становится жёлтой; зоны двигаются
  мышью, колесо приближает картинку, зажатая ЛКМ на пустом месте двигает её.
  Повторное нажатие сохраняет зоны, масштаб и сдвиг. При запуске режим всегда
  выключен; при переходе на другую вкладку он сбрасывается.
- Триггерные режимы `hold` / `repeat` читаются из `gamepad_data.trigger_modes`
  и передаются в `Worker`. Обычные привязки и триггерные режимы хранятся
  раздельно: одна кнопка геймпада может одновременно реагировать на обычное
  нажатие одной клавиши и на удержание/повтор другой.

### 4.6. Вкладка «Макросы» и эмблемы

- Устроена как «Мышь»: сверху виджет со скриншотом, снизу таблица, между ними
  разделитель.
- На скриншоте можно выделить мышью область — так задаётся участок, где будет
  эмблема. При отпускании кнопки в `settings.json` пишутся
  `left/top/right/bottom/width/height` в пикселях исходного изображения.
- Колонки таблицы: **Координаты**, **Клавиша**, **Скрипт**. Все три тянутся
  мышью, ширины сохраняются.
- Клик по «Клавиша» открывает большую виртуальную клавиатуру **без текстового
  редактора**; клик по «Скрипт» — ту же клавиатуру вместе с полем ввода.
- Структура данных: **путь к игре → путь к скриншоту**, затем
  **скриншот → координаты эмблемы, клавиша, скрипт**. Всё в разделе
  `macro_data`.

## 5. Редактор скриптов

- Клик по клавише виртуальной клавиатуры (на вкладке «Клавиатура», в окне
  «Полная виртуальная клавиатура» или в редакторе) открывает окно: сверху поле
  ввода скрипта, снизу клавиатура.
- Нажатие клавиш на этой клавиатуре вставляет в поле готовые команды `xte`
  (`xte "keydown …"` / `sleep 0.5` / `xte "keyup …"`) через `add_text_pytq5`.
- При закрытии редактора скрипт сохраняется в `keyboard_script` активного
  профиля; пустой скрипт удаляет запись. Для кнопок мыши — в `script_mouse`.
- Клавиши и ячейки «Скрипты» с назначенным скриптом подсвечиваются жёлтым.
- Скрипты подхватываются мышиным движком без перезапуска программы.
- При чтении/записи строки скриптов нормализуются (`scripts_to_text`): старые
  большие отступы продолжений убираются, поэтому команды в редакторе идут
  ровно без лишних пробелов. При первом запуске существующий `settings.json`
  очищается от таких отступов автоматически.

## 6. Эмуляция

### 6.1. Мышь и клавиатура

Скрытый `MouseSettingApp` из `library.py`:

- перехватывает физические кнопки мыши и нажатия клавиатуры (`evdev`, `pynput`);
- сопоставляет кнопки мыши с клавишами/скриптами текущего профиля;
- поддерживает режимы «удержать», «повторить» с интервалом 5/10/20 секунд;
- эмулирует нажатия через `evdev.UInput` с fallback на `xdotool`;
- при смене профиля или привязки получает свежие данные и пересоздаёт рантайм;
- при закрытии программы останавливается и отпускает залипшие кнопки,
  восстанавливая заводскую карту кнопок мыши.

### 6.2. Геймпад

`Worker` из `library.py` — перенесённая из рабочего редактора
`Editor_settings_for_Xbox360.py` реализация (класс совпадает с ним дословно):

- создаёт виртуальный геймпад Xbox 360 через `UInput`
  (`Microsoft X-Box 360 pad`, vendor `045e`, product `028e`);
- ищет физическую клавиатуру Logitech (затем любую подходящую), восстанавливает
  состояние NumLock и при включённом `grab` перехватывает её через `evdev`;
- читает обычные маппинги и триггерные режимы выбранного профиля;
- для кнопок с `hold`/`repeat` вычисляет итоговое состояние по схеме
  **удержание ИЛИ повтор-импульс ИЛИ обычное нажатие** и отправляет событие
  только когда значение изменилось;
- D-pad и стики обрабатываются немедленно. Направление стика берётся только из
  последней части имени: `LEFT_THUMB_RIGHT` означает `RIGHT`, а не `LEFT`.
  Знаки по стандарту Xbox: вверх/влево — отрицательное, вниз/вправо —
  положительное. Устаревшая реализация искала подстроки `LEFT`/`RIGHT` в любом месте
  имени и потому путала эти кнопки и инвертировала оси;
- правый стик объединяет клавиатуру и мышь: `REL_X`/`REL_Y` умножаются на
  `sens_x`/`sens_y`, при `smooth` сглаживаются, а затем плавно возвращаются
  в ноль;
- ЛКМ / ПКМ / средняя кнопка мыши эмулируют правый триггер, левый триггер и
  нажатие правого стика;
- при отсутствии мыши, ошибке захвата или отключении устройства захват
  снимается и виртуальный геймпад закрывается;
- запускается автоматически при старте, останавливается кнопкой, клавишей
  **End** (глобальный hotkey) или **ESC** в потоке эмуляции.

Одновременный запуск второго экземпляра редактора Xbox 360 дополнительно
защищён `flock` в `/tmp/xbox360_gamepad_emulator.lock`; здесь для этого
используется собственный lock-файл `/tmp/rewasd_linux_single_instance.lock`.

## 7. Скриншот по F11 (важно)

**F11 выполняется в любом случае, независимо от того, что сейчас показано на
экране.** Моментальный снимок делает `mss` с `monitors[1]` (основной монитор),
то есть захватывается **весь экран как есть** — рабочий стол, браузер или
игровое окно на полный экран. Неважно, какая программа сейчас в фокусе:
горячая клавиша глобальная, а захват идёт на уровне X-сервера, а не из окна
Qt. Окно программы при этом может быть скрыто в трее.

- Папка: `Screenshot_from_games/` рядом с `ReWASD.py`, создаётся автоматически.
- Имя файла: `ИМЯ_ТЕКУЩЕГО_ПРОФИЛЯ_ДАТА_ВРЕМЯ.png`, например
  `Alien_Isolation_2026-11-19_14-45-47.png`. Недопустимые символы в имени
  заменяются на `_`.
- После сохранения путь показывается в строке информации вкладки «Макросы».
- Горячая клавиша F11 ловится **глобально через `pynput`**, а не через
  библиотеку `keyboard`: последняя на Linux требует root и просто не
  регистрировала хук, поэтому скриншот раньше не создавался. Для фокусированного
  окна дополнительно работает обычный Qt-шорткат.
- Ограничение: под Wayland `mss` и `pynput` могут не работать — нужен
  X11/XWayland (как и в оригинальном проекте поиска по скриншоту).

Полученный скриншот можно сразу открыть кнопкой «Добавить» на вкладке
«Макросы» и выделить на нём рамку эмблемы.

## 8. Единый `settings.json`

Файл содержит **всё**. Основные разделы:

| Раздел / ключ | Что хранит |
|---|---|
| `profiles`, `profile_paths`, `current_profile` | Список профилей мыши, пути их игр, выбранный профиль |
| `mouse_data` | Данные движка мыши: `games_checkmark`, `paths`, `key_value`, `mouse_press`, `script_mouse`, `keyboard_script`, `current_app`, `id`, `id_name` |
| `gamepad_data` | Профили геймпада, триггерные режимы, чувствительность, `grab` |
| `gamepad_map`, `gamepad_profile_names`, `current_gamepad_profile`, `trigger_modes` | Рабочее состояние геймпада в интерфейсе |
| `gamepad_zone_geometry`, `gamepad_zoom`, `gamepad_pan`, `gamepad_split_sizes` | Зоны, приближение, сдвиг и ширина панелей геймпада |
| `mouse_map`, `mouse_hold`, `mouse_repeat`, `mouse_repeat_sec` | Привязки и режимы кнопок мыши |
| `mouse_splitter_sizes`, `mouse_column_widths` | Размеры панелей и колонок вкладки «Мышь» |
| `kb_split_sizes`, `kb_column_widths` | Размеры вкладки «Клавиатура» |
| `macro_data`, `macro_splitter_sizes`, `macro_column_widths` | Эмблемы, скриншоты и размеры вкладки «Макросы» |
| `main_splitter_sizes`, `profile_vertical_sizes`, `profile_split_sizes` | Ширина бокового меню и размеры блока профиля |
| `window_geometry`, `window_size` | Положение и размер окна |

Любой разделитель или колонка записывает новое значение сразу после
перетаскивания. При запуске все значения применяются; ширины колонок мыши —
после показа окна из трея, пока окно скрыто размер таблицы ещё не настоящий.

## 9. Закрытие, сохранение и выход

- При открытии окна из трея делается **снимок настроек**. При закрытии текущее
  состояние сравнивается со снимком по содержимому, а не по флагу.
- Если отличия есть, появляется окно **«Выход»** с вопросом «Вы хотите сохранить
  изменения перед выходом?» и кнопками **Сохранить / Не сохранять / Отмена**.
  «Отмена» оставляет окно открытым; «Сохранить» записывает JSON и обновляет
  снимок; «Не сохранять» возвращает и файл, и данные в состояние открытия.
- **Важно:** `save_settings()` только записывает файл и НЕ обновляет снимок.
  Его вызывают многие обработчики — смена профиля, ползунки, разделители,
  флажки геймпада. Раньше каждый такой вызов обновлял снимок, поэтому при
  закрытии всегда получалось «изменений нет», и диалог не появлялся. Теперь
  снимок обновляется только при открытии окна и после выбора «Сохранить».
- Автоматическая подгонка колонок при показе вкладки **не** считается
  изменением — окно не спрашивает просто так.
- Диалог появляется один раз; повторное срабатывание `closeEvent` подавлено.
- Кнопка закрытия завершает программу полностью, а не уводит в трей.
- Выход через меню трея задаёт тот же вопрос и затем завершает программу.
- Статус-бар «Готово / %» удалён — вместо этого действия подтверждаются
  всплывающими окнами и подписями.

## 11. Трудности и решения (история отладки)

1. **Сборка 8 файлов в 3 без потери логики.** Исходники склеивались механически
   по AST: удалялись только межмодульные `import` и блоки
   `if __name__ == "__main__"`. Остальной код вошёл дословно — проверено
   построчным сравнением.
2. **Медленный импорт `deepdiff` с диска** (больше минуты) тормозил запуск —
   импорт перенесён в функцию, где он реально используется.
3. **Стрелка выпадающих списков не рисовалась** из-за `border:0` в QSS —
   добавлен `assets/arrow_down.png`.
4. **Пересекающиеся зоны колёсика и кнопок** — введён приоритет: сначала мелкие
   зоны, потом крупные.
5. **Картинка геймпада не масштабировалась** при разворачивании окна — виджет
   переписан, зоны считаются относительно фактического прямоугольника картинки.
6. **Несовпадение зон/подсветки клавиатуры** — причина в `rect()` вместо
   `geometry()`; итог: настоящий `KeyboardWidget` в `QGraphicsView`.
7. **«Пружинящие» колонки** — минимальная ширина считается по тексту заголовка,
   освободившееся место отдаётся соседней колонке.
8. **Медленный старт на этом диске** (Qt/accessibility) — иногда требует
   повторного запуска, на логику не влияет.
9. **Перенос мышиного движка без смены интерфейса** — `MouseSettingApp`
   создаётся скрыто, вызывается `start_startup_now`, при закрытии рантайм
   останавливается.
10. **Редактор скриптов из окна мыши** перенесён в основную программу с
    сохранением в те же разделы JSON.
11. **Ложный вопрос о сохранении.** Автоподгонка колонок при показе вкладки
    меняла данные и сохраняла их — убрано из авто-подгонки, снимок обновляется
    только при реальном действии.
12. **Движок держал настройки в памяти.** Интерфейс менял JSON, но не память
    движка — добавлена синхронизация `save_jnson` + `set_cur_app` и
    пересоздание рантайма.
13. **Ширины колонок мыши не сохранялись** — отсутствовал вызов `save_settings`
    в обработчике перетаскивания; добавлен. Плюс нормализация больше не
    выполняется, пока окно скрыто в трее.
14. **Двойное появление окна выхода** — подавлено флагом `_closing` и
    гарантированным завершением процесса.
15. **Профиль «По умолчанию» терялся** — теперь вставляется автоматически.
16. **Переименование по двойному клику по выпадающему списку** — добавлен
    отдельный обработчик.
17. **Иконка в трее была маленькой/неаккуратной** — сделана простой и чёткой
    128×128, отдельная иконка окна 256×256.
18. **F11 вообще не срабатывал**: библиотека `keyboard` на Linux требует root,
    вызов `on_press_key` молча падал в `try/except`. Переведено на глобальный
    слушатель `pynput` + локальный `QShortcut`; проверено нажатием F11 — папка
    `Screenshot_from_games` и файл создаются.
19. **Огромные отступы в скриптах** достались из старого JSON: continuation-
    строки имели по 14 пробелов. Применена нормализация `scripts_to_text` при
    чтении, записи и однократно при запуске — команды отображаются ровно.
20. **Диалог «Сохранить изменения» не появлялся при закрытии.** Причиной было
    то, что `save_settings()` обновляла снимок настроек при каждом вызове, а её
    вызывают смена профиля, ползунки и флажки. После правки снимок обновляется
    только при открытии окна и при явном «Сохранить»; «Не сохранять» теперь
    восстанавливает не только файл, но и данные в памяти. Проверено тестом:
    смена профиля и параметра геймпада теперь обнаруживаются при выходе.
