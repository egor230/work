## 2. Перенос рабочего принципа геймпада в «комбайн»

Проблема: в `library.py` использовалась устаревшая логика стиков — направление
искалось подстрокой `LEFT`/`RIGHT` в любом месте имени, из-за чего
`LEFT_THUMB_RIGHT` читался неправильно и знаки осей были инвертированы.

Что сделано:

- `Worker._dispatch` в `library.py` приведён к рабочей версии из
  `Editor_settings_for_Xbox360.py`: направление берётся только из последней
  части имени, вверх/влево — отрицательное, вниз/вправо — положительное.
- Вкладка «Геймпад» (`ReWASD.py`, тогда ещё `main.py`) получила флажки
  **«Мышь»**, **«Сглаживание»**, **«Захват клавиатуры»**; `mouse_on` и
  `smooth` больше не жёстко `True`, а берутся из настроек.
- Удалён мёртвый метод `page_settings()` с дублирующими виджетами.
- `start_emulation()` перед запуском останавливает прежний поток — иначе
  изменения привязок не применялись.

## 3. Баг с диалогом сохранения и ревью по трём направлениям

**Причина бага:** `save_settings()` после записи JSON вызывала
`_take_baseline()`, то есть обновляла «снимок» настроек. Раз её вызывали
смена профиля, ползунки и флажки, к моменту закрытия снимок всегда равнялся
текущим данным — `has_changes()` возвращал `False`, и окно «Сохранить
изменения?» не появлялось.

**Исправление:** `save_settings()` только пишет файл; снимок обновляется при
открытии окна и после явного «Сохранить». «Не сохранять» теперь возвращает и
файл, и данные в памяти.

Затем был проведён трёхсторонний ревью (сохранение/профили, жизненный цикл,
движок геймпада). Найденные и исправленные проблемы:

| Группа | Что исправлено |
|---|---|
| Данные | скрипты из редактора больше не теряются; привязки геймпада пишутся во все копии профиля; `save_settings()` не затирает внешние правки `mouse_data`; индексы кнопок мыши приведены к порядку движка; старые JSON не удаляются при миграции; `ReWASD.sh` делает `cd` в каталог приложения. |
| Жизненный цикл | глобальные хоткеи доставляются в GUI через `hotkey_sig` (QTimer из потока pynput не работал); lock снимается при закрытии крестиком; убрана рекурсия при битом lock; `setQuitOnLastWindowClosed(False)`; отложенный `finished` старого Worker больше не портит состояние кнопок; убрано двойное `wait()`. |
| Эмуляция и UI | 7 зон кликались не в те кнопки — теперь 25/25 по центрам; ползунок дёргал движок на каждом тике — добавлена задержка 400 мс; оси помнят удерживаемые направления; кнопки мыши синхронизированы с `last_output`; End работает внутри потока при захвате клавиатуры; устройства закрываются в `_clean()`. |

## 4. Голосовое управление

Добавлена пятая вкладка **«Голос»** на основе
`Project/pytq6 volce game contol.py`:

- переключатель режима с двумя пунктами **Онлайн** (speechtexter через
  браузер) и **Оффлайн** (GigaAM с микрофона);
- фразы собраны в одном виджете-колонке слева, выпадающие списки клавиш —
  справа. Между ними `QSplitter`, ширина колонки фраз сохраняется в
  `voice_data.split_sizes`;
- кнопки «Добавить/Удалить команду», «Старт/Стоп», статус распознавания;
- стрелка у выпадающих списков (в QSS подставляется абсолютный путь к
  `assets/arrow_down.png`), подсветка при наведении на список, его пункты и
  границу разделителя;
- тяжёлые библиотеки (`numpy`, `sounddevice`, GigaAM, Selenium, `libs_voice`)
  импортируются только при нажатии «Старт»;
- исправлена ошибка запуска: каталог `Project` добавляется в `sys.path` **до**
  импорта `ctc_sber_gegaam_without_cuda` и `libs_voice` (ранее импорт выполнялся
  раньше добавления пути и падал с `ModuleNotFoundError`);
- остановка потока корректно проверяет флаг `running`; `pkill chrome` из исходного
  скрипта убран — закрывается только созданный драйвер;
- в выпадающий список команд добавлены «Без действия», левая/правая/средняя
  кнопки мыши, боковая левая (назад), боковая правая (вперёд) и колесо.
  Пункты мыши стоят в начале списка и названы явно. Раньше список содержал
  только клавиатурные клавиши, а `work_key.key_press` не умеет мышь — теперь
  такие команды выполняются через `pynput.mouse`. Цифровые клавиши
  переименованы из `key1…key9` в `1…9` и без префикса сохраняются в JSON;
  старые значения `key1` при загрузке приводятся к `1`.

**Настройки перенесены в единый JSON.** В `settings.json` появился раздел
`voice_data`: 11 команд, профиль `vosk`, `start_startup: true`. Исходный файл
`settings_voice_game_control_linux.json` в кодировке cp1251 читается правильно
(русские фразы, а не кракозябры). Миграция не удаляет исходный файл.

### 4.1. Назначение кнопок мыши в вкладках «Мышь» и «Геймпад»

Ранее списки назначения начинались с `KEY_0`, `KEY_1`, … — кнопок мыши в них
не было вообще. Исправлено:

- `ASSIGN_MOUSE_ACTIONS` добавляет в начало любого списка назначения пункты
  **левая/правая/средняя кнопка мыши**, **боковая левая (назад)**,
  **боковая правая (вперёд)**, **колесо вверх/вниз**;
- **префиксов `KEY_` и «Мышь:» в подписях нет**; порядок: кнопки мыши
  по-английски (`Left button`, `Right button`, `Middle button`,
  `Side button left (back)`, `Side button right (forward)`, `Wheel up`,
  `Wheel down`), затем стрелки `Up/Down/Left/Right`, затем буквы `A…Z`,
  цифры и `F1…F12`. Включена видимая полоса прокрутки
  (`setMaxVisibleItems(12)`, `ScrollBarAlwaysOn`, стили QSS);
- в `Worker` введены виртуальные коды `MOUSE_ACTION_CODES` (отрицательные, не
  пересекаются с `evdev KEY_*`): `XBUTTON2 = -5`. Событие `BTN_EXTRA`
  (у pynput — `button9`) теперь проходит через тот же путь, что и клавиша:
  обычный маппинг, hold/repeat и комбинированная логика; колесо даёт импульс
  нажатия/отпускания;
- выбор в комбо сохраняется через `itemData`, поэтому в JSON пишется
  `XBUTTON2`, а не русская подпись; старые значения `KEY_*` продолжают работать.

## 8. Мышь Maxxter (18f8:0f97): подсветка, DPI и скрытый отчёт 7

Дополнительное исследование «по просьбе пользователя»: выяснить, какая мышь
подключена, и можно ли программно управлять её чувствительностью и подсветкой.
Результаты на этой машине (28 ноября 2026).

### 8.1. Что подключено

```
Bus 001 Device 008: ID 18f8:0f97 [Maxxter] Optical Gaming Mouse [Xtrem]
```

| Параметр | Значение |
|---|---|
| VID / PID | `18F8` / `0F97` (то же железо, что Jedel GM680 и Genius Gaming Mouse) |
| Прошивка | `bcdDevice 1.00`, имя `USB OPTICAL MOUSE` |
| Интерфейс 0 | `hidraw3` — мышь, Report ID 1, **5 кнопок**, X/Y по 12 бит, колесо |
| Интерфейс 1 | `hidraw4` — клавиатура (Report ID 3), consumer (ID 2), vendor input (ID 6), **vendor FEATURE report ID 7** |

Именно report 7 (Usage Page `0xFF01`, Usage `0x20`, 7 байт данных) оказался
единственным каналом, через который мышь вообще может принимать команды от ПК.

### 8.2. Важное свойство report 7

Проверено отправкой `07 01 02 03 04 05 06 07` с последующим чтением:

```
SET -> 07 01 02 03 04 05 06 07
GET <- 07 01 02 03 00 00 00 00
```

**Вывод:** прошивка хранит и использует только первые **три** байта данных,
то есть формат команды — `[opcode, p1, p2]`; байты 4–6 игнорируются.
Поэтому все «цветовые» байты в ранних экспериментах (см. 8.4) не влияли
на результат — реально отправлялись только значения `opcode/p1/p2`.

### 8.3. DPI-кнопка не видна операционной системе

Два независимых сеанса сниффера (raw `hidraw3`/`hidraw4` + `evdev`
`event6`/`event7`) с просьбой нажать DPI-кнопку 3–5 раз показали:

| Событие | Что зафиксировал ПК |
|---|---|
| DPI-кнопка | **ничего** — ни HID-отчётов, ни evdev-событий |
| Левая кнопка | `01 01 00 00 00 00`, `BTN_LEFT` (code 272) |
| Средняя кнопка | `01 05 …`, `BTN_MIDDLE` (code 274) |

Кнопка обрабатывается целиком внутри прошивки мыши и не посылает хосту
никакого сигнала. Программно перехватить её нажатие невозможно; переназначить
её на что-то программными средствами тоже нельзя.

### 8.5. Как была отключена подсветка и DPI

Команда, которая отправлялась в конце серий 1 и 2 и совпала с наблюдавшимся
эффектом — **все нули**:

```
07 00 00 00 00 00 00 00
```

Наблюдения пользователя:

- после серии 1 (завершалась нулями): «Изменился цвет/подсветка», затем
  «сейчас никакого цвета нет»;
- «я мог изменить через кнопку DPI, сейчас она не меняется» — то есть
  DPI-кнопка перестала переключать чувствительность;
- серия 3 была оценена как «ничего не менялось» (но она тоже заканчивалась
  нулями и начиналась с них).

**Оценка:** наиболее вероятно, что `opcode = 0x00` — это «отключение»:
выключает подсветку и фиксирует DPI, из-за чего аппаратная DPI-кнопка
теряет способность что-либо переключать. Причинность не доказана на 100%:
переподключить мышь для контрольного восстановления возможности не было,
а часть наблюдений противоречива. Ни один из ненулевых opcode надёжно
работающим не подтвердился.

### 8.6. Скрипт

Добавлен `mouse_hid_disable.py` (копии в `work/ReWASD_linux/` и
`Project/mouse/`):

```bash
sudo python3 mouse_hid_disable.py status   # прочитать report 7
sudo python3 mouse_hid_disable.py disable  # отправить 07 00 00 … (по умолчанию)
sudo python3 mouse_hid_disable.py set 07 01 02 03 00 00 00 00
```

Скрипт сам находит `hidraw`-интерфейс мыши по VID/PID в sysfs
(берёт интерфейс 1, где висит report 7), отправляет команду **дважды**
(некоторые прошивки применяют её не сразу) и читает результат обратно.
Требует root — `/dev/hidraw*` доступны только root.

Для практических экспериментов по подбору команд рядом лежит
`mouse_hid_tool.py` (`info`, `get`, `set`, `sweep`, `dpi`, `rgb`).

### 8.7. Ограничения

| Ограничение | Причина |
|---|---|
| Точный протокол DPI/RGB неизвестен | Прошивка принимает SET_FEATURE молча, GET возвращает только то, что записали; ответов нет. |
| Надёжной команды «включить обратно» не найдено | Переподключение мыши недоступно; EEPROM/volatile-поведение не проверено. |
| Цветовые команды не работали | Байты 4–7 report 7 прошивкой игнорируются (см. 8.2). |
| DPI-кнопку нельзя переназначить ПО | Она не генерирует HID-события вообще (см. 8.3). |

Для полного расшифрования протокола нужно оригинальное ПО **Genius Gaming
Mouse** и перехват его USB-трафика (USBPcap под Windows или `usbmon` под
Wine) — это даст точные команды вместо догадок.
